# PA 产品视频与截图制作

将真实 PA 操作制作成可读、可重剪的素材。优先复用官方 skill、现有工程和已通过的
检查，避免临时摸索按钮、猜配置或自建媒体工具。

## 先确定输入与范围

- README 的故事、分镜、截图 ID、备用剪辑及托管规则，以[素材准备指南](../../../docs/development/workflows/readme-media-production.md)为准；不要在本 skill 复制维护。
- 区分本次是工具短样片、正式拍摄，还是已有工程后期。记录目标库/窗口、允许录制的
  内容和产物目录；沿用当前任务已有授权，不重复确认同一操作。
- 录制不自动授权模型付费调用、上传或发布。工具验证优先复用非敏感测试笔记和已有
  结果；正式故事中的模型任务按实际授权执行，不伪造输出或主动提示。
- 录制工具检查可使用已有测试实例并说明版本，不等于当前 PA 源码已部署验收。
  若任务包含 PA 改动的应用验收，再使用[测试库验证](../obsidian-test-vault-smoke/SKILL.md)。

## 先用现成能力

1. 如已安装官方 `cap` skill，先读取；否则读取[官方入口](https://github.com/CapSoftware/Cap/blob/main/apps/cli/skill/cap/SKILL.md)。
   命令以当前安装版的 `cap guide --json` 和必要子命令帮助为准，不猜参数。
   MCP 未加载时可以直接用 CLI，不为一次本地任务重装 Cap 或修改全局配置。
2. 根据任务选择必要部分；官方/第三方 skill 的适用范围及已验证命令见
   [Cap 工作参考](references/cap-workflow.md)。网页短片和口述视频流程不直接套到 PA。
3. 使用当前可用的 Computer Use 操作 Obsidian、选择录制源和观察界面；采集、工程
   读写和导出有结构化接口时用 Cap。不要把观察用截图循环当作连续录像。

## 拍摄与最小验证

- 先记录 Cap/CLI、Obsidian、PA 实际构建及目标窗口。读取 `doctor` 的
  `captureReady` 和具体检查，不能只看退出码或 `ok`。
- 在受限执行环境中出现 `denied`，先区分执行环境与 macOS 隐私授权；按工具权限
  机制使用正常本机环境复核。确实缺少权限时让用户完成系统授权，不绕过限制。
- 首次截图或录制前，及 Cap 版本或自动化设置变化后，先按
  [Automations 检查](references/cap-workflow.md#采集前核对-automations)核对匹配规则。
  GUI、CLI 和短样片均适用；有超出当前授权的自动动作时，先解决再采集。
- **Cap 0.6.2 录制 PA 的已验证选择是界面 Window + Focus 模式。** 同版 CLI 的
  `--window` 实测会采集窗口所在的屏幕区域，其他前景窗口可能混入；截图接口
  正确不代表录屏已隔离。更新版若要替代此路径，先用短样片确认实际画面。
- GUI 选源后核对是目标 Obsidian 库，并按需测试菜单、模态框和来源跳转。选源控件
  无法可靠操作时，请用户协助这一个步骤，再继续；记录人工配合，不声称全自动。
- 首次接入或相关版本/窗口/采集方式变化时，先拍最小短样片，查看起始帧及动作后
  画面，确认目标正确再投入正式录制。相同条件已有有效证据时复用。
- 按当前故事保留必要连续原片；工具短样片不代替真实主动发现、Memory 检索、
  Writing 保存或生图的运行证据。没有主动提示时采用指南中的备用剪辑并保留缺口。
- CLI 录制保存 `recordingId`，明确结束；只有 `recordingMetaExists:true` 才认为
  停止完成。GUI 录制核对停止后的工程。用已知产物目录或当前工程定位文件，
  不默认扫描全部录制库。

## 截图与后期

- 关键状态就地保存原始 PNG，保持笔记、PA 界面与成果的关系。不要仅靠压缩后视频
  抽帧制作主图；原始截图与发布副本分别保留。
- 先复制 `.cap` 工程到本次产物目录，只修改副本；避免同时由编辑器和 CLI 写入
  同一工程。保留原片、完整配置以及镜头的源片起止时间。
- `project config set` 是完整替换：先读取并保留无关字段，再写回与回读。字幕、
  缩放和剪切的版本化示例见参考；不要把编辑配置传给编码用的 `--settings-json`。
- 静音影片用手写意图文字轨，不为加字幕先做语音转录，也不按静音自动删除阅读、
  核对来源或保存确认。剪短等待需说明。
- 小菜单用局部特写，随后回到产品情境；字幕不要遮住操作目标。先看关键预览帧，
  再完整导出，发现具体问题才改对应段落。
- 16:9 在工程中明确设置 `aspectRatio:"wide"`；仅给导出分辨率不保证改变画布比例。
  像素、码率和体积都不能代替 README 默认宽度及窄屏下的可读性检查。

## 验收与交付

分别核对以下证据，不以单个成功回执代替全部验收：

| 要确认什么 | 最低充分证据 |
| --- | --- |
| 录到了正确窗口 | 原片起始帧、关键动作及结尾；独立窗口需要检查遮挡条件 |
| 操作与结果真实 | 对应镜头的实际菜单、来源、选择及结果；未覆盖步骤保留未验 |
| 工程可继续使用 | 原件保留，副本经 `project validate` 和配置回读通过 |
| 字幕、缩放与剪接正确 | 导出关键帧、剪接边界和代表性完整播放 |
| 成片规格正确 | `Completed` 路径、实际文件，以及 ffprobe 或 QuickTime Inspector 的编码/尺寸/帧率 |
| README 可读 | 默认显示宽度及窄屏预览，不可读时调整字号、取景或特写 |

优先用已有 Cap、ffprobe 或 QuickTime 完成检查，不为一次验证临时编写解码器或
安装另一套录制软件。交付可编辑工程、原件位置、视频、截图发布副本，以及简短的
版本/范围/剪辑说明和未验证项。工具验证、正式素材验收、上传和 README 替换分别报告。

素材存放及托管沿用制作指南；不把新录屏原件或成片加入 Git，不因录制任务自行恢复
指南中暂缓的自动循环动图或 P5 结构断言。结束后停止录制，恢复本次改变的 Obsidian 页面/模式/草稿，保留用户
主动选择的设置；提交、上传与发布按各自授权执行。
