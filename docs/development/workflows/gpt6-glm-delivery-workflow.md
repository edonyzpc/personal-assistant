# GPT-6 / GLM 开发交付流程

Document status: Current
Updated: 2026-10-05
Authority: [GOV-001](../governance/gov-001-agent-managed-project-lifecycle.md#gpt-6--glm-delivery-allocation) 下的 coding agent 操作流程。

## 默认路径与读集

**GPT-6 定边界 → GLM 连续开发与验证 → GPT-6 独立验收 → 清理环境。**
质量和需求满足是固定门槛，优先减少重复调查、重复上下文及无效检查。
GPT 接管实现后的审查分级见 §3；不把实现者自查称为独立审查。

- GPT-6 负责产品讨论、设计、派工、权威文档和 Tracker；GLM 通过独立 Codex CLI
  承担限定调查、实现、测试、自查及获派验证，不自行改需求、验收标准或标记完成。
- GPT-6 按本流程和 [任务模板](../templates/glm-worker-task.md) 派工；GLM 只读任务单、
  适用的 AGENTS 和必要契约，不例行加载整份主控流程。当前上下文已读且未变的事实
  直接复用；新 worker 必须得到所需事实和已接受的校正，不能假定继承主会话记忆。
- 首次安装、配置变更或接入错误才读 [GLM 环境配置](./glm/setup.md)。
  日常不扫描会话、采集额外 token 或生成成本报告；专项研究才使用已有日志，
  缺失数据填未知，不从不同任务推算节省比例。
- 用户入口：“按 GPT-6 / GLM 流程推进这个需求。”常规工作在已有授权内连续完成；
  仅未定产品取舍、实质偏差或超出授权的操作交用户决定。
- 用户已持续授权：为完成本项目已授权任务，可向现有 `pa-glm` / `ZAI` 端点发送
  必要 PA 源码、测试、契约与脱敏工具输出。同范围派工、修订和恢复不重复申请。
  不发送私人 vault、秘密、敏感原始日志或其他项目材料；新增 provider/端点或扩大
  数据范围须交用户决定。此授权不扩大实施范围、Git/release 或凭据操作权限。

## 0. 接入与任务预检

同一主机的 CLI、provider/model、catalog、鉴权和工具权限未变，且已有可核对证据时，
复用接入预检；配置变化、新错误或证据失效只重验受影响部分。

首次接入按配置参考核对非秘密配置身份，依次验证无工具认证、read-only 工具调用，
以及 scratch 中创建/修改文件、测试成功和预设失败的自然退出。不向产品注入错误。
模型自述、配置文件存在或退出码 0 均不能单独证明工具能力或交付成功。

每个任务只补核对变化与实际边界；当前上下文已有且未变的事实直接复用：

- 实际 cwd、基线与已有修改、允许编辑范围、交付目标，以及 runner/关键依赖与锁文件。
  GLM 可在同一上下文开头检查，不另开环境调查会话。安装依赖按实际需要及授权执行，
  共享依赖的写入由 GPT-6 协调。
- 实际 provider、端点、模型/推理参数、CLI/catalog 身份及影响本次调用的覆盖。
  配置身份可引用有效记录；服务端实际型号无证据时记未知，不读取或散列密钥。
- 指定验证所需的工具、权限和本机 app/vault 目标。CLI 不自动继承桌面工具；
  只能调用 GPT 模型的工具不能冒充 GLM；额度接管按 §5 的已授权策略执行，说明
  实际执行者，不静默替换角色。

## 1. GPT-6 准备任务

按 [Documentation Workflow](../documentation-workflow.md) 选择最轻文档路径。
已有工作从 Feature Home + Tracker 进入；窄修在任务消息保留必要字段即可，
不额外创建完整 package。GPT-6 维护唯一执行状态，GLM 返回待核对报告。

PA Agent/runtime/command 任务先应用 [Command Architecture Contract](../../architecture/pa-agent-architecture-plan.md#command-architecture-contract)。
GPT在已有SDD/任务单写明本切片关键决策/准入/状态/副作用的owner与事实依据，传给GLM；
只引用统一定义，不按当前command的局部规则反推新架构。

任务单固定：目标与完整 REQ/AC、负例、不可变约束、非目标、必要读集、工作树及
已有改动归属、允许编辑/生成范围、交付终点、验证分工和临时资源。每项风险对应
“变化 → 最低充分证据/命令 → 通过条件 → 重跑触发”，不用完整调查替代派工。
app/mobile 验收写明环境及其用户要求或当前契约依据；环境路由遵循 AGENTS，
不把 Agent 自拟计划、技能选择或工具故障当成新增必需门禁的依据。

默认一个 GLM writer，使用隔离 worktree/工作分支；用户指定当前 checkout 时保护
已有 dirty diff。新 worktree 不会自动带入未提交契约，GPT-6 显式提供并核对当前
任务和文档。不得用 stash/reset 丢弃用户修改；Git 权限仍遵循 AGENTS。

## 2. GLM 连续执行

| 模式 | 选择条件与终点 |
| --- | --- |
| `deliver`（默认） | 目标、预期明确且低风险；同一上下文简述理解后连续调查、回归、实现、自查、获派验证，统一交付 |
| `understand` | 根因/范围不清或存在技术选择冲突；只读调查后由 GPT-6 固定实施边界 |
| `reproduce` → `implement` | 持久化、权限、迁移、复杂异步/跨模块不变量或已证实同类交付失效；先固定设计和负例，核对目标失败后实施 |
| `fix` | GPT-6 已确认的缺陷；按修订任务修复并复测受影响项 |

范围冲突或未定选择只暂停受影响步骤，继续独立授权工作。新 mock/fixture 接线错误
可自行修正；不得弱化断言、改正确预期迎合实现或改变命名技术选择。重要回归保留
实现前测试 diff、目标失败与修复后证据；导入/依赖错误不算目标红灯，机械修改和
可复用证据不强制造红灯。高风险不能因任务小而自动归入 `deliver`。

先准备完整非空任务单、准确工作树和每次独有的输出目录，再按已核对配置启动：

```bash
# 路径变量须已解析；只添加已核对的 provider/model/MCP 等覆盖。
codex exec --profile pa-glm --cd "$pa_worker_tree" \
  --sandbox workspace-write --json \
  --output-last-message "$pa_run_dir/result.md" \
  - < "$pa_run_dir/deliver-task.md" \
  > "$pa_run_dir/events.jsonl" 2> "$pa_run_dir/stderr.log"
```

只读任务使用 read-only sandbox。核对完整输入、实际进程与工具事件，分别保留自然
退出码；等待进程结束后再认定交付。空报告、失败或中断不能当成功；审批阻塞交主会话，
不使用 `danger-full-access` 或绕过权限。使用完成通知/有界等待，只读新增摘要，
保持必要用户进度沟通，不逐命令监督，也不自动推进未获派的下一切片。

双方均在调用前限定输出：定向读源码；程序比较大型基线，仅返回变化路径；压缩
产物只提取目标规则。完整日志留本地，返回结果、数量、退出码和必要失败片段；
`head` 限行不能限制压缩长行，截断不能充当完整核查。GLM 不启动嵌套 agent，
不改模型配置、Tracker 或 authority，不 stage/commit/push/merge/tag/publish；
本地部署只执行任务单指定目标。

## 3. GPT-6 验收与接管后的审查

按 [项目 review 规则](../../../.agents/skills/personal-assistant-review/SKILL.md)，先读
契约、实际 diff、关键断言和原始结果，再核对 GLM 报告。检查：

- 相关变更先核对四角色职责与真实调用链；Host每项硬条件有明确权限/运行事实依据。
  可修正错误与实际/未知效果分开，确定性fixture不冒充Agent模型语义或app交互。
- 完整变更范围与基线、任务修订及约束一致，含未跟踪、删除和生成文件。
- 每个 AC/负例有真实行为或断言支撑，既有测试未被弱化，正确测试分组确实运行。
- 命令、自然退出、输入身份、构建/部署和实际 app 目标可核对；未运行、失败、
  阻塞与未验证分别记录，尚缺必需门禁不能标为 Done/Validated。
- 已达到约定交付终点。目标树接收后输入变化则补受影响检查；相同输入证据可复用。
  独立验收靠独立判断，不要求 GPT-6 重跑 GLM 已完成的全部检查。

新架构、复杂状态等可按风险安排独立只读 reviewer，不给每个小任务固定增加角色。
GPT 按 §5 接管实现后，按用户于 2026-10-02 批准的风险规则选择审查方式：

- 发布门禁、数据/权限、迁移或跨模块行为：必须由实现者之外的只读 reviewer
  审查，可以仍用 GPT；reviewer 先核对契约、实际 diff 和证据，当前 writer 负责修复。
- 低风险文案、局部样式、恢复既有契约的窄修：允许 writer 自查，加必要测试或
  实际交互验证；记录为自查，不宣称独立审查。风险由实际影响决定，不以文件数
  或修改行数决定；一个发布条件的窄修仍属于发布门禁。
- 反复返工、范围不清或证据冲突时升级为独立审查；已有明确的独立 review、阶段、
  app/device、CI 与发布要求不因此豁免。

在现有 Tracker/任务记录中注明风险、实际 writer、自查/独立审查及适用的 reviewer。
必需 reviewer 暂不可用时保留未验证，不由 writer 自行标为独立审查通过；继续独立
授权工作。主会话核对 reviewer 结论与修复结果后更新唯一验收状态。

发现问题按 [review followup](../../../.agents/skills/personal-assistant-review-followup/SKILL.md)
确认严重度、触发条件、违反的 AC 和修复/复测范围；返工由当前 writer 执行，校正
进入新修订。默认 GLM；已按 §5 接管的任务由 GPT 继续，不因额度恢复自动切回。
P0/P1/P2 依项目规则关闭或明确处理后才完成阶段。只有 GPT-6 更新验收状态；
验收不授予 commit、merge 或发布权限。缺少后续授权时明确产物位置和待办。

## 4. 验证调度

命令、测试分组、证据复用及门禁以 [AGENTS.md](../../../AGENTS.md#testing-instructions)
为准：docs-only 跑文档检查，窄修先 focused suites，共享行为/基础设施按 broad gate，
artifact tests 使用当前 build。不改变原有阶段、CI、release 或实机要求。

对新增或改变的外部 API/Host 接线，先核官方 API 形状和最小真实调用链；公共协议
变化优先复用既有兼容用例。先解决足以推翻当前实现的边界问题，再安排昂贵完整门禁，
不把每个局部修补拆成一次完整验收。相关修复收束后冻结输入，集中完成该阶段门禁。
这些定向检查不能冒充 app 交互；实际部署仍遵循 AGENTS Local Deployment，
不能为提前 smoke 绕过 `make deploy` 或 `deploy-current` 的复用前提。

GLM 在工具与权限已验证时执行获派 focused/full tests、lint、build、docs 和本地部署。
最终昂贵 gate 由一个执行者对冻结输入运行；重跑须有相关输入变化或具体的新诊断假设，
失败本身不是重跑理由。
证据复用和失效条件统一按 AGENTS Validation Planning And Reuse 执行，
独立验收核对真实差异和原始结果，只补缺失或失效的证明；发布要求仍由发布门禁执行。
复用 `make deploy` 已覆盖的检查；满足条件时使用 `deploy-current`，不把构建身份
当作测试通过。部署前核对实际 vault 与已加载插件，worker 构建成功不等于目标 app 已更新。

共享工作树并行时，在已有任务单中区分 worker 的局部验证和统一检查。全仓 TypeScript
检查由指定执行者在相关输入冻结后收口，生产 build 已覆盖时复用；因具体跨模块风险
安排的提前诊断仍可执行，但不要求每个 worker 在他人持续修改时取得共享树全绿。
新增并行任务或改变验证分工时，将变化实际送达受影响的在途 worker，不能只更新
Tracker、新 worker 或下一轮任务。若当前 CLI 无法即时送达，原任务中的外部阻塞
停止条件仍须生效；主控在下一次可送达时更新分工，不假定 worker 已获知。

UI 任务按改动面验收：纯样式用已验证 CLI/deep link 准备真实组件状态，再观察并
操作受影响动作；修改菜单、入口、焦点或选区时必须实际走该入口。CLI/DOM 准备
不能代替可见交互。GLM 缺少 app/device 工具时由具备能力的执行者补齐，GPT-6
可负责真实视觉验收。工具刷新一次后同因再失败，改用支持的等价方法；无法覆盖
必需交互时保留未验证，不以截图或 CLI 成功冒充通过。

## 5. 升级与恢复

明确的额度错误直接走额度分支，不使用通用失败的再次重试预算。区分 CLI/provider
内部自动重试与 GPT 主动重启，按原始事件归因；主控停止新增即时探测。AGENTS
不能控制客户端内部重试，未确认当前 CLI 支持错误分类前，不声称已修复该层行为，
也不关闭全部网络重试。若另行调整客户端，只对明确额度错误禁用即时重试，保留
短暂网络故障恢复；配置变更仍按既有配置流程处理。

| 情况 | 处理 |
| --- | --- |
| 同因第二次失败且无新信息，或诊断约 15 分钟无进展 | 停该项重试，返回准确错误；GPT-6 换诊断路径并修订任务。健康长测试不受此限制 |
| 常规范围需要扩大 | GPT-6 核对与契约兼容后更新任务；未定产品取舍、实质偏差仍交用户决定 |
| GLM 周限额 | 按用户预授权立即由 GPT 接管；先执行下述 writer 停止与交接 |
| GLM 5 小时窗口限额 | 已知 reset 在首次确认限额后的 1 小时内则等待，到 reset 正常续跑一次；超出 1 小时直接由 GPT 接管 |
| GLM 限额类型或 reset 未知 | 只读取一次现有可用额度信息；仍未知则由 GPT 接管，不重复模型请求探测 |
| 认证、协议或必需工具不可用 | 与额度故障分开诊断；保留现场与下一步，继续独立工作，不套用额度接管或盲目重试 |
| 越权改 authority、伪造证据或破坏性操作 | 中止 worker，核对差异，暂停扩大职责并重新验证 |
| 经诊断不适合 GLM 实现，且不属于上述额度策略 | 说明具体缺口与替代方案；未获授权的实施者或范围变更仍交用户决定 |

同因工具调用或报告交付失败第二次且无新信息时，停止恢复同一失败路径。
若 GLM 仍能可靠修源码，只把缺失检查交给工具可用的执行者，GLM 保持 source writer；
在原任务中更新验证分工，先确认旧检查命令已结束，再补缺失证据。
不因此重做预检、已通过的检查或整轮实现；source 接管仍须符合上表条件。

等待截止固定为首次确认限额时间加 1 小时，不因重试或 reset 更新滚动延长。
等待时继续独立授权工作；截止先到或一次正常续跑仍被限额则 GPT 接管，不再探测。

恢复或接管前确认旧 GLM worker 及其写入命令已停止；输出沉默不代表结束。
新任务修订继承实际 diff、已通过且输入未变的证据、接受校正、否决路径和未完成项，
不重做无关预检、测试或输入清单，不盲目重放写入。接管后不因额度恢复自动切回；
记录实际执行者，GPT 实施不计作 GLM 独立成功，按 §3 完成风险匹配的审查与既有门禁。
失败现场保留到完成诊断/接收；不丢弃用户改动。

放宽某类任务步骤须有该类重复证据，保留独立验收；少数任务通过不证明其他类别
能力。返工或遗漏增加时恢复所需检查点，不以降低质量换成本。

## 6. 验收通过后的环境清理

交付与必要 gate 通过、完成 §3 要求的审查和验收且产物安全接收后，由 GPT-6 协调清理：

1. 将必要结论和证据归入已有任务记录；迁移交付文件时先确认副本可用、更新链接。
   原始日志在验收前不得删除，仍被引用的唯一证据保留。
2. 确认 worker 与写入命令结束；只停止本任务可核对的临时进程，恢复临时 app 状态，
   保留用户原有会话、设置和视图。
3. 按创建时记录的精确路径删除可丢弃临时输入、脚本、scratch、冗余日志/截图和
   合成数据；不扫删 /tmp、不追随符号链接删除共享资源，回归 fixture 属于交付物。
4. 临时 worktree 仅在交付已接收、没有独有修改/未保留文件且普通 remove 可成功时
   移除；不使用 force、git clean/reset 或删除分支/提交制造干净状态。保留未提交
   源码、共享依赖、当前构建/测试插件及稳定 GLM 配置。

GLM 随创建记录资源，报告待清理项，不能自验收后删除证据。确定性清理无需另开
模型会话，也不重复未失效测试。报告“交付通过”和“清理完成/部分完成”，说明
保留原因；不扩大 Git、凭据或项目归档权限，不宣称未执行的清理已完成。

## 7. 多设备独立运行
