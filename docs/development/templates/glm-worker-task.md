# GLM Worker Task 模板

由 GPT-6 填写，供 [GPT-6 / GLM 流程](../workflows/gpt6-glm-delivery-workflow.md)
派发一个可验收行为切片。清晰低风险任务默认 `deliver`，连续完成开发和获派验证；
仅歧义或高风险增加检查点。有 Tracker 时沿用其任务小节，窄任务可用任务消息。
窄修填写下列三项即可。按实际改动补充对应条件，进程输入使用任务单的临时副本。

## 简短派工单

```text
任务 {{ID / 修订 / 标题}}。你是 GLM worker，按 {{deliver 或指定模式}} 执行并交回报告，GPT-6 独立验收。
结果与依据：{{从哪个入口观察到什么结果，引用可访问的契约/REQ/AC，写明通过条件}}
范围与终点：{{授权工作树、允许修改/生成的范围、交回终点。可引用标准基线、接收树、运行目录及已核实的执行者、端点、材料范围和预检记录}}
验证分工：{{GLM 执行哪些检查，各方复用哪些证据，GPT-6 据什么验收}}

按条件补入对应项，删去其余提示：
- 可能影响旧设置、共享调用方、权限、迁移或并发行为时，写出具体约束、代表性负例与验证方法，可引用已有回归用例。
- Agent/command 任务附架构契约、关键事项的 owner 与 Host 判断的事实依据。
- 布局或交互任务给出现有界面、截图或原生控件参照及目标状态。
- 有相关未提交改动、并发写入或接收树输入差异：写明归属、受影响的证据及补验范围。
- 返工或切换上下文时附已核实的事实、接受的校正、否决路径、前一 writer 的状态和剩余工作。
- 需要统一检查或准备依赖时，指定执行者、所需输入与命令。
- 涉及部署、设备、额外临时进程或数据恢复时，写明目标、执行者、必要观察与恢复责任。app/mobile 环境注明用户要求或契约依据。

执行纪律：
- 遵守 AGENTS.md；产品工作获得 North Star 与当前契约。当前上下文已读且未变的
  内容直接复用，只补读变化、缺失、反证或先前截断的段落，不假定继承主会话记忆。
- deliver：按已授权的结果连续实施、自查和验证，可逆细节由执行者决定。
  重要回归保留目标失败日志、测试 diff 和对应输入，优先复用能识别该回归的证据。
- understand：只读调查后返回；reproduce：只写/跑指定测试，保留生产实现后返回。
  implement/fix：按已确认范围实施与验证。所有模式完成后停止，不推进下一任务。
- 兼容的局部实现和新 mock/fixture 接线错误可自行修正；不改变正确行为预期。
  不改 authority、验收标准或 Tracker，不删除/弱化断言，不用 skip/forceExit 造通过。
- 命令执行前限定读取范围和输出上限。大型基线由程序比较，只返回变化路径；
  生成/压缩 CSS 只提取目标规则，不 cat 整份清单或打印压缩整行，head 限行不够。
  原始日志留在本地，返回结果、数量、退出码和必要片段；截断不能冒充完整核查。
- 每次重跑须有相关输入变化或具体的新诊断假设；失败本身、等待时间或猜测他人已修复
  都不是重跑依据。同因失败第二次无新信息，停该项重试并报告。
- 共享检查失败先核对与本次改动的因果，不能仅按报错文件归属排除自身影响。确认是
  其他任务造成且与本次改动无关后，记录错误与归属、报告一次，停止该项检查并继续
  独立工作；归因不明先定向诊断。收到相关修复或输入冻结的实际通知后，按分工补验；
  未通过的检查保持未验证，由指定执行者收口，不因局部完成而记为通过。
- 纯样式任务优先用已验证的 CLI 或深链接准备目标状态，再观察实际渲染并操作受影响的控件。
  菜单或入口本身有改动时，必须实际操作该入口。工具状态刷新一次后同因再失败，切换支持的等价方法；
  无法覆盖必需动作就报告未验证，不以 CLI 成功代替，也不自行更换指定验收环境。
- 范围冲突、实质偏差或必需工具/权限缺失时报告证据，继续独立授权工作；不绕过 sandbox。
- 不读取凭据或完整用户配置，不修改模型配置，不启动嵌套 agent。
  不 stage/commit/push/merge/tag/publish；本地部署仅执行任务单明确授权的目标。
- 随创建记录本次临时资源/恢复项；验收前保留证据和现场，不自行清空运行目录。
  正常结束自建临时进程并恢复已完成验证的临时状态；最终资源删除由 GPT-6 验收后协调。
```

配置详情沿用 GPT-6 已核对的非秘密记录：主机、CLI、profile、provider/端点/协议、
请求模型/推理参数、catalog 身份、覆盖项、鉴权方式名称及预检证据。服务端型号
无证据填未知；不输出或散列密钥。任务单只传必要配置和可访问的证据引用；worker
无法访问的主会话事实需附简短摘录，不要求它重查含凭据文件或重做已通过的预检。

## GLM 一次交付报告

```text
任务 / 修订 / 模式：
结论：待验收 / 调查完成 / 回归待核对 / 阻塞（不能自报已验收）
实际 diff 位置与范围：工作树、基线、涉及的路径及改动目的，含新增、删除和生成文件。
检查范围与结果：对应 AC、实际行为或断言，以及可核对的原始记录位置。
交回终点与缺口：自查结果，失败、未运行、未验证或需决定的事项。涉及接收、部署或临时资源时注明剩余动作及恢复情况。
```

已有记录可访问，且能核对实际命令、执行范围、自然退出及对应输入时，引用一次即可。
信息不全时补上可核实的缺项，其余标为未验证。适用的输入包括代码、测试、夹具、
配置及依赖，涉及构建、部署或 app 观察时还需匹配相应环境与产物。

日常无需额外采集用量、扫描会话或编写效率报告；执行器已有用量/计时可附路径，
不估算费用或重跑命令补统计。中途仅在出现阻塞、
决策冲突或重大新风险时主动上报；正常阶段进展简短即可，不逐条请求 GPT-6 批准。

## GPT-6 集中验收卡

在现有 Tracker 或窄任务记录中写结论。GPT-6 先对照契约独立核查实际 diff、
相关断言与原始结果，再核对 GLM 报告。按
[证据复用规则](../governance/gov-001-agent-managed-project-lifecycle.md#validation-planning-and-reuse)
判断记录对接收树当前输入是否有效。

```text
实际 writer、风险、审查方式及适用的 reviewer：
授权终点与结论：对照任务范围和各 AC 记通过、未通过或未验证，引用相应 diff、断言或原始结果。
必要的补验或返工：写明输入变化、证据失效或缺少哪项必要行为，只复核受影响范围。必要项仍未验证时保留缺口，该项待验收。
适用事项：Agent/command 的职责与真实调用链，部署/实际 app 观察，需用户决定的产品选择，验收后资源清理与保留项。
```

GPT 接管时按工作流 §3 选择审查方式：发布门禁、数据/权限、迁移、跨模块行为须
由另一位只读 reviewer 审查；低风险自查不得写成独立审查。其他明确要求的门禁保留。

仅用户明确要求的流程试点/复盘才在已有记录简记 GPT-6 实质干预、各模型用量及
阶段耗时；日常保留质量与返工证据即可。一次性接入和用户等待单列，缺失填未知，
无可比基线不报节省比例。
