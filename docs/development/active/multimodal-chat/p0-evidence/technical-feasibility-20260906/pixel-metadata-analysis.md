# B-129 图片像素、元数据与小字质量验证

日期：2026-09-06。独立检查实际原件和输出文件；不依赖原型的成功状态判断
像素、元数据或可读性。完整 hash、输出位置、EXIF、像素值、裁剪坐标及定量
对照保存在 [JSON 回执](pixel-metadata-analysis.json)。

## 结论

两端原件完整性、方向、白底合成与敏感元数据处理通过。**小字证据不支持把
2048 作为所有图片的无条件输出尺寸**：本次 3200 宽截图中原有 12px 文本，
缩到 2048 后仅剩 7.68px；iOS 连 3072 的轻微缩放也比未缩放输出明显柔化。
尺寸参数必须区分预览与语义内容，不能让缩略图替代发送给模型的图片。

小字实验建议的 **3200 长边、JPEG quality 0.9**，已由后续双端单张及 8 张
48 MP [资源补测](./resource-host-analysis.md) 核对，并由 SDD 采纳为实施
默认值。在此尺寸内保持原始像素尺寸，不做多余缩放；截图和文字细节不得
仅为节省字节而静默降到 2048。该结论不代表生产集成已经完成。

## 小字对照

同一份绘图逻辑在两端生成 3200×1800 白底截图，含黑色 monospace 字体的
12/16/24/36px 文本。宿主字体及栅格化可能不同，因此先比较各自未缩放输出，
不假定两端原始 PNG 字节相同。

使用 Pillow 从各张输出截取原始像素，**没有 resize 或放大**。截取区域包含
12px 与 16px 两行文字，在 1:1 下独立目视判读。裁剪文件仅作临时观察，JSON
保留原图 hash、裁剪坐标与裁剪 hash，可从指定 test vault 文件重现。

| 输出长边 | 12px 原字的有效尺寸 | Desktop JPEG | iOS JPEG | 1:1 判读 |
|---|---|---|---|---|
| 1536 | 5.76px | 26,820 B | 42,476 B | 字符极小，细笔画合并；不能作为通用文字保真默认值 |
| 2048 | 7.68px | 45,265 B | 67,617 B | 仍能辨出部分已知文本，但笔画明显变细、对比度降低；iOS 更软 |
| 3072 | 11.52px | 80,158 B | 131,462 B | 比 2048 清楚，但轻微重采样仍损失细节，iOS 尤其明显 |
| 3200 | 12px，无缩放 | 88,829 B | 150,736 B | 两端本次最清楚，保留原字尺寸和较清晰的笔画 |

一个辅助指标也支持上述观察：12px 行非白像素中，平均 RGB ≤64 的深色像素
比例，在 Desktop 2048/3072/3200 分别为 5.42%/12.88%/32.55%；iOS 分别为
0%/0%/24.07%。这仅描述细笔画的深色对比度，不是 OCR 正确率，也不是模型
已理解文本的证明。

### 参数使用约束

- 预览可使用较小副本；provider 与正式笔记分别采用自己的副本策略。
- 文字、截图或用户明确要求读取细节时，先保持来源像素；在本次受测的
  3200 长边范围内不缩放。不能只因文件叫图片便统一采用照片压缩参数。
- 2048 可作为明确不要求文字细节的可选策略，不能成为所有图片的默认降级。
- 超过长边、单图或本轮字节预算，仍保留原件和草稿，明确说明细节限制并让
  用户提供局部或调整素材；不能静默降低清晰度后声称完整处理了文字。
- 本报告的 3200 小字验证使用 5.76 MP 截图；原 12/24/48 MP 阶梯测至 3072。
  后续 3200 的单张及 8 张 48 MP 串行、内存及字节预算核对见
  [最终资源分析](./resource-host-analysis.md)，不扩大本报告的小字样本范围。
- 没有发起真实模型 OCR 请求；provider 自身的缩放仍可能影响结果。没有
  证明任意大截图的小字都能保留，也未验证通用自动文字分类器。

## 两端图片完整性与元数据

Desktop 01 的 20 项，由 Desktop 02 的 6 项补齐 SVG 修复证据，合并 22 种
输入；iOS 完整 22 项。原三份回执共 48 行、21 个 JPEG 输出，均用实际文件
复核，原件和输出 hash 与回执一致，JPEG MIME、尺寸和可解码性一致。
两端对应原件逐字节相同，处理成功或需要静态图片的状态相同。

逐项证据来自本目录归档的 `desktop-formats-01.json`、
`desktop-formats-02.json` 和 `ios-formats-01.json`；小字原始回执为
`desktop-resources-01.json` 与 `ios-resources-01.json`。JSON 中记录各份
实际回执的 hash。图片保持在对应 test vault，不复制进文档目录。

| GPS HEIC 核对 | Desktop | iOS |
|---|---|---|
| 原件 SHA256 | `2148dd7786d833605bfca3b545263072bb9c7cd35c759e454f8a18a10846a1c1` | 同左 |
| JPEG 字节 | 32,777 B | 46,829 B |
| JPEG 尺寸与方向 | 480×640，像素已应用 orientation 6 | 相同 |
| GPS / Make / Model / 拍摄日期 | 均无 | 均无 |
| 原完全透明区域 | 白色 (255,255,255) | 相同 |
| 原半透明洋红区域 | (255,127,254) | 相同 |

本次另用 macOS ImageIO 直接读取当前源文件，确认原 HEIC 仍含合成 GPS、
`B129 SYNTHETIC CAMERA`、`FICTIONAL MODEL 000`、拍摄日期
`2000:01:01 00:00:00` 和 orientation 6。Pillow 与 ImageIO 均确认两个
输出 JPEG 已去掉上述来源字段，旋转已应用到实际像素。

Desktop JPEG 保留 JFIF/ICC；iOS JPEG 仍有新生成的颜色空间、像素尺寸 EXIF
及空 IPTC 的摘要。**不能把通过结论表述成“没有任何元数据”。**

静态 PNG/WebP、JPEG 与 HEIC 的四角色块对合成目标最大单通道误差为 1，
半透明洋红合成误差不超过 2；全透明区域按白底处理。已目视检查两端 GPS
HEIC 输出和 iOS 普通 HEIC 输出，色块、透明区域及 12px 图表文本可见且正确。
此处图表原宽为 640，没有经过大截图缩小；不与上方小字缩放限制混淆。

## 证据边界

- 仅覆盖合成 sRGB 8-bit 静态图片，不外推真实相册取得、HDR、广色域或
  多主图完整理解。
- SVG 拒绝回执证明对应输入在外层图片解码前被拦截；计数不是系统抓包证据。
- URL 计数相等证明原型释放了拥有的引用，不证明系统图像解码器即时释放
  全部物理内存。原件 hash 是实际文件证据；草稿恢复仍需后续生产集成验收。
- 旧回执没有覆盖；修复后的 SVG 验证作为补充证据保留。
