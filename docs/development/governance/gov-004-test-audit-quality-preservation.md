## Context And Selected Governance Choice

目标是使测试真正捕获有意义的回归，并减少重复维护与脆弱等待。允许审计发现需要
新增测试，甚至使数量增加；不设删减比例、目标 case 数或未经实测的提速指标。

本契约承接 [GOV-003](./gov-003-proportionate-test-design.md) 的适度测试、输入隔离、
coverage 与发布保护要求。优先保护 [North Star](../../product/pa-product-north-star.md)
所需的笔记完整性、来源可信、权限、恢复与不阻塞的正常使用。GOV-003/B-142 的历史
交付状态不因 B-150 重开或改写。

参考已于 2026-09-26 阅读的 OpenClaw [test-audit](https://github.com/openclaw/openclaw/blob/main/.agents/skills/test-audit/SKILL.md)
与 [CAMPAIGN](https://github.com/openclaw/openclaw/blob/main/.agents/skills/test-audit/CAMPAIGN.md)：
按生产责任边界判断独立价值，删除前说明保留证据，并专门复核丢失的保护。PA 使用
风险切片与现有 Jest/GPT-6/GLM 流程，不移植其工具链或全仓逐条 campaign。

本文保存稳定设计；执行期间由 owning Tracker 记录基线、候选、进度和验证结果。
B-150 完成后的独有裁决与验收依据见[审计验收快照](../../archive/2026/b150-test-audit/final-report.md)，
[覆盖地图](../../archive/2026/b150-test-audit/coverage-map.md)保留本轮已审/未审边界。
完整职责地图不等于全部测试已深审，历史快照不替代后续实际发现集合或执行状态。

## Requirements

- B-150/REQ-01：地图覆盖实际 Jest 发现的全部测试，包括共置于 `src/` 的测试和
  关联辅助文件；每份测试有生产职责归属、执行分组、证据层级与深审状态。
- B-150/REQ-02：按可观察契约和可信失败场景判断价值；选择主要测试位置，其他层
  说明独立风险。新增、改写和保留测试使用同一价值标准，允许补足真实漏测。
- B-150/REQ-03：删改前建立契约承接关系；合并必须保留不同前置状态、失败原因、
  临界点与时序。行为契约删除/合并必做独立保护复核，证据不足则保留待查。
- B-150/REQ-04：来源、权限、取消、持久化、恢复、真实 CLI/Git、签名/重放和构建
  身份等独立保护继续成立。基线失败先诊断，不以失败作为删除理由；产品修复另列。
- B-150/REQ-05：保持正确测试发现、coverage 统计范围/阈值和现有门禁；冻结输入、
  验证自然退出并记录复用边界，不用 skip、forceExit、放宽正确预期或增加 timeout 换绿灯。
- B-150/REQ-06：最终交付限测试、夹具及测试辅助代码；生产清理单列。按既定模型
  分工执行，Tracker 为唯一状态权威，不把计划、抽样、局部 PASS 或 CI 当作更广证据。
- B-150/REQ-07：已授权的临时变异限拟删改的关键权限、来源隔离与数据安全保护；
  在隔离副本进行目标失败验证并精确恢复，生产代码最终零改动。

## Scope And Non-goals

允许交付的文件用途为测试、fixture、mock 和 test helper，包含实际被发现的
`src/**/*.spec.ts` / `src/**/*.test.ts`，不能仅按顶层目录判断。生产代码可为审计
只读追溯；临时变异只按下述协议操作，不形成产品修改。

本轮不迁移 Jest、升级依赖、调整构建配置、测试分组政策、coverage 门槛/忽略项、
CI 并行数或发布流程；不创建通用测试平台、全仓 mutation framework 或额外计时
服务。不默认发送笔记给真实 provider、使用付费调用或变更 live vault。

静态断言、mock、慢测试、私有访问和大文件仅是线索。API、协议、配置、存储、
迁移、平台、提示内容、包/发布与架构契约可能需要这些手段，不能按模式批量删除。
标为 test-only 的接口也必须核查真实调用，生产清理候选不顺手实施。

## Audit Design

### 1. 全仓职责地图

以实际 Jest discovery 为全集，比较 source/tooling/artifacts 与完整入口的并集和
交集。文件改名、新增或经批准删除后，按裁决更新预期集合；完整发现不是要求测试
数量恒定，而是防止保留测试从路由中意外消失。共享 helper 标记使用方和写入归属。

每份测试记录：路径、分组、生产 owner、契约、层级、关键 mock/fixture、重叠证据、
基线出处和深审状态。按实际导入、调用与断言归属，不仅看文件名前缀。跨模块测试
指定一个主要责任边界并链接其他边界；未知项明确待查，不能自动判为低价值。

### 2. 按风险选取完整的小切片

完成地图后选一个生产责任边界作为首批，完成调查、修改、定向验证和独立保护复核后
扩展；最终完整门禁按下述 Owner 决定集中执行，全部通过前不接受总体交付。
一个切片内完整阅读涉及的用例和参数表，不仅抽取搜索命中的 expect。
建议依次覆盖 Agent/Chat、Memory/VSS、Capture/写入、Pagelet/UI、tooling/发布；
具体优先级由可信失败风险、证据薄弱程度与近期变更决定。

每个领域可以拆成多个小批次。全仓地图若发现唯一安全保护无效，立即提高其优先级；
不得因领域排在后面而接受失去保护。未审部分保留“未审”，不由抽样外推结论。

### 3. 候选裁决与测试写作准入

裁决前阅读完整测试、生产 owner、入口/调用者/下游、相关历史、重叠测试、CI 路由；
依赖真实行为有争议时查已安装依赖的源码或类型。用一张紧凑卡片记录同一契约的
候选组，避免为机械重复创建庞大台账：

| 必需字段 | 要回答的问题 |
| --- | --- |
| 定位与契约 | 精确测试名称/位置、生产 owner、可观察结果是什么？ |
| 可信失败 | 哪种错误会让它失败？是否确实到达目标 guard 或副作用？ |
| 历史与调用 | 为什么存在？被覆盖的接口有哪些非测试调用者？ |
| 证据真实性 | 哪部分是真实路径、哪部分由 mock/fixture 提供？预期是否独立？ |
| 承接与独立性 | 保留哪条具体测试/断言？它为何能捕获同一缺陷，或为何原项没有独立契约？ |
| 拟改与验证 | 保留、修正、合并、删除或待查；受影响文件/使用方、命令和未解风险是什么？ |

新增/改写测试须说明保护的结果、可信回归、现有证据为何不足，以及能否通过现有
生产边界验证。优先扩展适当的参数表或 fixture；不同参数行保护不同风险时分别
裁决。禁止用被测函数计算期望、由 mock 实现目标行为或让无关早期拒绝充当目标失败。

“主要测试位置”不意味着只保留一种层级：规则矩阵、真实接线、存储/网络边界和
宿主行为可有独立价值。不得用一条大型集成用例吞并其无法准确触发的失败路径。

### 4. 先承接保护，再删除或合并

保留测试已有独立证据时直接引用；缺证据时先改写或补足，并证明其有效后再删。
无意义的样式字面量/测试自证按 GOV-003 说明无独立契约的依据，不制造同类替代测试。
有疑问的候选保留；增加有效测试可以是审计成果。

每次行为契约删除或合并，由非该变更作者独立核对旧断言与保留断言的承接关系。
在现有 GPT-6 验收环节完成即可，无需额外固定角色或重复全量运行。复核特别检查：
唯一保护是否消失、不同拒绝原因是否仍可区分、参数行是否能到达目标、预先生成的
receipt/授权/回调顺序是否掩盖缺失生产行为。不得把实现者自查作为独立验收。

### 5. 受限隔离变异协议

Owner 于 2026-09-26 对“第一点按照建议推进”的明确答复授权本节；符合本节的验证
无需逐例再次确认。适用对象限拟删除、合并或修复的关键权限、来源隔离与数据安全
保护。优先用现有公开输入/fixture 构造反例；需要验证断言辨别力时使用最小变异。

1. 记录隔离副本、生产与测试输入身份、目标契约、精确用例和受影响文件原始哈希。
   确认保留测试在正常实现上通过；已有等价、输入可核对的证据可以复用。
2. 固定测试与输入，每次只制造一个有契约含义的最小生产错误，例如移除目标来源
   检查。确认测试因目标断言失败；导入、编译、超时、环境或无关 guard 失败不算反证。
3. 变异未被捕获时，先判断路径未到达、变异未改变目标语义或测试缺口；保留候选
   待查，必要时修正测试。不通过改生产正确行为、放宽预期或增加等待上限制造绿灯。
4. 等待验证进程退出后逐字节恢复生产文件，核对哈希及 diff，再验证同一用例通过。
   变异构建产物与正常验收产物隔离；只恢复源码不足以证明实际执行的 bundle 已恢复。
5. 保存基线通过、目标失败、恢复通过的命令/输入/原始结果、自然退出和恢复证据。
   变异版本不提交或部署；恢复失败时停止该副本后续使用并保留现场，不继续验收。

该协议不授权持久生产修改、全仓 mutation campaign 或新增生产测试接口。候选尚无
足够反证时不能声称等价保护已成立；最终审计交付的生产代码必须与接受的基线一致。

### 6. 失败、回滚与停止条件

| 情况 | 处理与恢复条件 |
| --- | --- |
| 基线测试失败 | 分开诊断产品、fixture/runner、环境和陈旧产物；真实产品缺陷保留复现并单列，不删除测试换绿灯 |
| 关键契约缺少保留证据 | 保留原测试或先补足；不能接受相关删项，其余独立切片可继续 |
| 负例未到达目标或变异红灯原因不对 | 本次证据无效，缩小复现并纠正验证输入；不标已验证 |
| 共享 fixture 引入串扰、开句柄或时序依赖 | 扩到全部使用方，保持可变状态独立并自然清理；同因重试按仓库诊断规则收敛 |
| 测试/源码/依赖/配置在检查中变化 | 停止或完成后明确标为旧/混合输入证据；重新冻结并补受影响门禁 |
| coverage 文件或统计分母意外减少 | 检查最后一个导入者与忽略/收集配置，恢复或补足真实覆盖；不得借统计范围变化维持百分比 |
| 临时生产文件或执行产物未恢复 | 隔离该副本，核对创建时备份/哈希并精确恢复；不得覆盖其他任务或用户改动 |
| 必需宿主/设备证据不可用 | 记录未验证，保留依赖该证据的删项；不以 mock、截图或 CLI 声称真实交互等价 |

每批保留可审阅的测试 diff 和原始验证证据。需要回滚时只撤回本批拥有的改动或
恢复其明确基线；不使用清空工作树或覆盖无关修改的方法。源码基线前移时重新核对
受影响契约，新增加的回归必须在候选中有承接；不能盲目保留旧删除结论。

## Validation And Acceptance Criteria

验证命令与门禁遵循 [AGENTS.md](../../../AGENTS.md#testing-instructions)。最低证据映射
在 Tracker 中按“风险 → 拟改 → 命令/证据 → 通过条件 → 重跑触发”维护。

- B-150/AC-01：地图覆盖实际发现全集，各分组不丢失或重复；最终集合与获准的
  新增/改名/删除一致。每份测试有 owner，未审项与辅助文件明确标注。
- B-150/AC-02：每个实际修正/合并/删除项有完整候选裁决，命名具体保留证据或无
  独立契约的依据；新增测试有独立风险，不由标题、数量或静态模式决定去留。
- B-150/AC-03：行为契约删减经过独立承接复核；漏测先补足，基线失败分类清楚；
  来源、权限、时序、数据和发布保护没有因结果相同或重复表象而被吞并。
- B-150/AC-04：所需 focused 与集中门禁实际运行且自然退出；保留原 coverage 门槛、
  忽略配置与源码统计范围保护，分支/场景承接另有证据，不能仅凭覆盖率达标验收。
- B-150/AC-05：每次采用的变异验证有目标明确的通过—失败—恢复通过证据；无效
  失败不计入，通过哈希/diff 和实际执行产物身份确认恢复。
- B-150/AC-06：最终修改面符合测试/夹具授权，生产代码零改动；模型/工具身份和
  实际部署目标按需核实，无越权产品修复、凭据操作、Git 或发布动作。
- B-150/AC-07：Tracker 的执行状态与证据一致；未审范围、未解 finding、证据限制
  和下一批均明确。P0/P1/P2 按仓库规则关闭或获明确处置后才接受相应批次。

集中完整验证前冻结 source/tests/fixtures/config/dependencies；一个执行者统一运行
lint、production build、完整 Jest coverage 和 diff check，不对每个删项重跑全量。
source/tooling/artifacts 使用正确入口；artifact tests 必须绑定当前 production build。
分组契约已包含在完整门禁时复用，不额外重复。

Owner 于 2026-09-26 在观察到本地同环境 coverage 基线耗时后，明确选择合并完整门禁：
每批仍完成定向测试、必要的关键反证与独立保护复核；所有本轮测试改动冻结后统一执行
一次 lint/build/完整 coverage/diff gate，并与 B0 核对路径、分母和保留场景。
这是 B-150 对原“每批分别完整验收”节奏的明确调整；不删减测试、降低覆盖率阈值，
也不把 targeted PASS 等同于总体验收。基线失败及最终失败仍按原诊断规则处理。

对比可核对输入的前后 coverage 报告，至少核对源码路径集合、各指标分母及被删
场景的承接关系。当前配置按已载入模块收集，不能假定门槛未改就代表分母未改；
同环境基线缺失时补一次必要基线，不能引用不同环境的百分比声称等价或提速。

测试限定改动不例行部署。删改理由若依赖宿主/设备等价性，必须复用仍有效的实际
证据或补适用 smoke；证据不足则保留候选。真实 UI/数据/权限行为若需修改，转入
相应产品修复范围。CI、最终 tag 与现有发布要求保持独立。

## Authority And Change Boundary

GPT-6 负责设计、任务切片、状态和独立验收；默认 GLM 按
[既定工作流](../workflows/gpt6-glm-delivery-workflow.md) 承担获派调查、实现和验证。
Owner 于 2026-09-26 明确选择“本任务改由 GPT-6 执行，不调用 GLM”；B-150 因此由
GPT-6 承担调查、测试修改与验证，使用非作者的 GPT-6 reviewer 独立复核。此选择仅
覆盖本任务，不修改其他任务的默认分工，也不授权向 ZAI 发送本任务材料。
默认一个 writer，共享 fixture 单一写入归属；只读 reviewer 不重复执行完整 gate。
未核实 provider/tools 时不派发，也不静默换模型实施。

已确认的范围与临时变异授权继续有效。需要持久生产修改、扩大临时变异边界、放宽
质量/发布政策、接受唯一保护缺失的风险或真实外部调用时，先说明具体证据和取舍，
只暂停受影响步骤；常规测试组织和准确分组由执行方自主处理。
