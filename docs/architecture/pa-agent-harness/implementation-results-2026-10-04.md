## 采用的实现

采用精简 Host、可读回的冷 Writing 历史，保留现有 Personal 注入。Pi/Hermes 的参考落实为清楚的职责：Agent 判断任务是否充分，Host 管真实边界，领域 owner 管状态；历史正文按需读回，Skill 方法逐级加载。没有移植另一套 Agent 框架，也没有新增反思 Agent、critic 或自动记忆选择器。

| 问题 | 最终处理 |
| --- | --- |
| U1 不同查询被误认作无进展 | 删除旧完成度账本、语义 epoch、按未知 receipt 分类的进展判断。仅以 Dispatcher 的真实规范化调用身份识别重放批次；不同查询可继续，未知副作用仍不重放。 |
| U2 旧 Writing 正文占满历史 | 当前会话增加 `read_writing_history`；合法、可取回且退出最近两整轮的独立 Writing 组变为显式引用。原正文/canonical 不改，当前 parent 保留；native/compat、预算及摘要规划使用同一准入版本集合。 |
| U3 Skill 被静默截断 | 入口与注册引用分别完整读取，Templater 长入口拆为可发现的引用；后续取消入口、单个引用与默认输出字符拒绝，物理模型窗口统一处理。 |
| U4 恢复建议没有查询工具 | 增加 `get_image_status`，绑定当前会话；本地快照与一次纯远端查询区分。无 providerTaskId 保持未知，不 submit/resume/save/cancel/poll。 |
| U5 Personal 是否应默认注入 | 实际两臂比较后保留现有策略，删除临时 off 开关。没有重做 memory extraction、存储、检索或风格选择。 |

旧 `pa-agent-required-capability-policy`、`pa-agent-answer-completion-policy`、`pa-agent-progress` 三模块共 874 行被删除；无消费者的 control budgetState 和派生器一并移除。Loop 保留实际请求/工具/时间预算、取消、保留终止轮和连续传输失败恢复；Pagelet/Operations 的领域约束保留。成功的 provider 轮次重置连续失败计数。临时候选路由与运行脚本退出生产树，保留案例和结果。

独立复核还修正两处接线：旧稿来源在物理模型发送前再次校验；摘要快照保留 writingVersionId，并使用冷历史的预算规划。普通历史确需辅助摘要时，摘要源仍可能包含旧稿正文；本轮没有声称消除所有辅助输入成本。

## 实验发现的额外修正

E-H3 暴露出一个可确定修复的事实丢失：整批在执行前被拒绝，canonical 明确记录 policy_rejected，但未知 lineage 加上正文清洁使发送给模型的结果变为 result_unknown。模型因此把已知“未执行”误解成工具通道中断。

修正使用 Dispatcher 在零执行分支创建的有限事实，绑定 callId/toolName、封闭 reason 和 not_started。实时准入依赖该对象身份，仍合并原调用来源；持久化副本只能展示有限事实。原拒绝正文继续隐藏，没有给来源或工具权限豁免。实际 SDK 记录端口回归确认第二次模型输入保留两个配对拒绝结果及原因，未泄露正文。

E-H3 的模型推断仍保留为解释问题；E-M3 的“不必要澄清”判定已撤销。此前围绕该评分进行提示优化与复测的依据不足，不能因保留了失败日志而忽略这一评估失误。最终没有新增判断器，不以任意问句数量、调用次数或单轮成品作为可靠性门槛。
