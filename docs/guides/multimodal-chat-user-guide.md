# 图片聊天与图文保存

适用于包含 B-129 的构建；是否已发布以实际安装版本及发布记录为准。产品范围见 [Product Spec](../product/specs/pa-multimodal-chat-product-spec.md)，历史验证与实机边界见 [验证证据](../archive/2026/b129-multimodal-chat-validation.md)。

本指南描述现有实现。2026-09-08 已确认的“统一实际交付文件、HEIC 先转 JPEG、
PA 保存时迁出聊天附件”是后续目标，尚不能按本指南中的旧转换/复制行为推定已交付。
实施差异与后续入口见 [Architecture](../architecture/multimodal-chat-architecture.md#图片管理修订与当前实现差异)。

## 加入图片并继续聊天

在 Chat 点输入框旁的图片按钮，选择从文件或当前笔记库添加；移动端另提供选择照片。桌面也可粘贴或拖入文件。每条消息最多 8 张，可只发图片，也可附带问题。沿用当前 Chat 模型；模型不支持图片时，需要在设置中切换，已有草稿会保留。

待发送图片集中在输入框内的缩略图栏。点击缩略图查看大图和文件信息，点右上角移除；移除草稿不会删除原图。处理中或失败的图片会显示状态，失败时按提示移除后重新添加。原始格式说明和打开、重新定位原图等操作可在图片详情中查看。

外部文件先保存在附件位置下的 `pa-images` 子目录。目录按这段聊天的关联笔记确定；没有关联笔记时使用笔记库根位置。切换当前编辑器不会移动已经保存的原图。从笔记库选择图片则引用现有文件。预览和模型使用处理后的副本，原件保持原字节，并可从聊天图片打开。

首次使用图片时会显示非阻塞说明：当前配置的 AI 服务商会接收处理副本中的可见内容。移除 GPS、拍摄时间和设备信息等源敏感元数据，不会遮住图片中的文字、人物或其他内容。可从设置 → Personal Assistant → 功能 → 聊天图片 →“管理已保存的原图”→“图片与 AI 服务商”再次查看；这条说明与同步排除状态分别记录。

原件可能仍含敏感元数据；正式笔记附件通常复制原件，HEIC 的正式 JPEG 则移除源敏感元数据并保留原件关联。原件与正式附件都不会因说明已读而被自动修改。

手机相册和粘贴可能先转换格式。图片详情出现“尚未核实原始格式”时，PA 已保留收到的文件，但不能保证它就是拍摄原件；需要提供另一份文件时，通过图片按钮选择“从文件添加”。图片缺失或被移动后，可重新定位内容完全相同的文件；内容已改动的图片应作为新图片添加。

已发送且持久化成功的聊天可在同一设备重新打开。手机、电脑分别可用，聊天历史不会随笔记库跨设备同步。未发送的文字草稿不承诺重启恢复，已经登记保存的原图仍可在原图管理入口找到。

## 图片格式与空间

首版处理静态图片。动画 GIF/APNG/WebP 和依赖外部资源的 SVG 会保留原文件，并提示提供静态 PNG/JPEG；不静默抽取动画首帧，也不联网补齐 SVG。

HEIC 优先通过设备已有能力在本地转换；macOS 原生解码失败时尝试系统转换。没有内置大型解码库、远程转码或自动安装。转换不可用时，提供 JPEG 后继续。保存含 HEIC 的笔记时，正式附件使用 JPEG；HEIC 原件留在原位置并保留来源关联。

处理采用有界队列和可清理缓存。单原件上限 20 MiB、解码上限 48 MP；较大的图片需先另存较小的静态副本再加入。超过请求预算时不会偷偷删掉某张图。原件、聊天处理副本与正式笔记附件是不同用途，存储量可能增加。

通过设置 → Personal Assistant → 功能 → 聊天图片 →“管理已保存的原图”，可查看实际原图路径、体积和已知引用，清除处理副本。清缓存不删除原图或正式附件。桌面删除原图需要单独选择并确认；iPhone/iPad 由 PA 打开原图，再在 Obsidian 文件管理中手动删除。已知引用不代表检查了所有笔记或其他 App。

## 保存文案与参考风格

明确要求“写文案”后，可从回答旁打开“文案版本”。正文与辅助说明分开。复制只取选定正文；修改后可以保留独立版本，也可从某个旧版本及其完整图片集合继续写。图片无论用于参考还是作为主题都会保留，不按角色丢弃。

展开“参考详情”可分别查看关联图片、背景来源和风格样例。背景来源可打开对应笔记的当前内容，可能与当时提供的内容不同；风格显示当时记录的确切样例。提供参考不代表模型已逐项采纳，也不代表旧笔记中的经历就是本次图片事实。

切换版本时参考记录随之切换。本地改稿沿用原版记录，没有再次请求模型；旧记录若无法确认本次提供范围，会明确说明。样例已更正、被遗忘或无法访问时显示不可用，不换成最新样例，也不从聊天正文恢复已遗忘内容。参考状态刷新不会清空正在编辑的文字。

“保存为笔记”时填写笔记标题即可，默认保存到笔记库根目录；展开“更改位置”可填写文件夹，不必在标题中拼接路径或 `.md`。默认选中该版本全部图片，展开“选择图片与调整顺序”可修改。预览核对标题、保存位置、正文和图片数量，需要时查看“保存详情”，也可返回修改；明确确认后才建立笔记并补齐图片及链接。原生附件目录设置以实际目标笔记为准。完成后可直接“打开笔记”；AI 原稿与实际修改稿保留来源区别，保存本身不授权风格学习。

中断后可能留下未完成笔记和部分附件。重新打开该版本，或从更多菜单进入“未完成的笔记保存”，核对后继续；该菜单项仅在存在未完成保存记录时出现。重试先检查已写内容，遇到修改或冲突会停止，避免覆盖。关闭保存窗口不会删除已写文件。

模型正常完成回复，且内容核对通过时，PA 可直接识别文案；整个回复只有一个完整、标注 `json` 的代码块时也支持识别，复制和保存仍只取文案正文。多个代码块、块外说明、格式错误、截断或取消的回复仍需手动恢复。

恢复时，原始响应只在“选取或编辑文案正文”中展示。选取正文后才形成可保存版本；仅选原文仍属于 AI 草稿，实际改字才属于用户修改稿。恢复不需要再次调用模型。

“以后参考这种风格”是另一个明确操作：确认确切文字与文案形式、目的、读者、主题，只用于匹配场景。当前要求优先；无法判断场景或预算不足时不自动使用。可在 Memory 查看、更正、暂停参考或忘记；暂停与忘记不会删除已保存笔记，也不能撤回已经发送给模型的内容。

仍使用旧个人资料的设备，可打开设置 → Personal Assistant →“Memory 与个性化”，在“升级此设备的已保存理解”中点击“检查并升级”。一次操作会核对全部旧资料及来源，成功后为当前设备的当前笔记库启用逐条管理和风格参考；其他设备需要分别处理。

升级不会自动修改或清理旧资料，不发送资料给 AI、不重建 Memory，也不开启自动学习。缺少来源、已有更正或遗忘尚未完成、检查期间资料变化，或无法确认来源稳定时，会说明原因并保持旧资料和旧模式，不跳过问题记录。不是所有旧资料都能升级；升级也不延长原有恢复期限。

## 分别配置三种同步

首次保存到某个原图目录前会显示实际路径。之后可在“管理已保存的原图”展开“图片存储和同步说明”。通知已读不代表配置完成，也无法确认文件是否曾经上传。正式笔记附件按普通附件规则保存，不继承原图目录的排除。

**Obsidian Sync：** 在每台设备打开设置 → Sync → Excluded folders → Manage，选择实际 `pa-images` 目录。目录变化后补充排除。设置不跨设备同步；排除不会删除远端已有文件。[官方说明](https://obsidian.md/help/sync/settings)

**Git：** 在笔记库根目录的 `.gitignore` 中加入实际目录规则。PA 尝试补充已有文件；无法更新时手动设置。插件说明会显示对应规则，示例：

```gitignore
/Attachments/pa-images/
```

已有 Git 跟踪不会因加入规则而停止，历史提交也不会消失。含特殊字符的目录应使用插件生成的转义规则并核对。PA 不自动取消跟踪、改写提交或删除远端文件。[Git 官方规则](https://git-scm.com/docs/gitignore)

**iCloud Drive：** PA 没有可靠的笔记库子目录排除能力；原图在 iCloud 笔记库内时，仍按可能上传处理。“保留下载”“移除下载”或备份设置不是禁止 Drive 上传。若必须不上传，需要自行选择本机笔记库或支持文件夹排除的同步安排，PA 不自动迁移笔记库或更改系统设置。[Apple 设置说明](https://support.apple.com/guide/icloud/set-up-icloud-drive-mm203b05aec8/icloud)

PA 的 AI 数据边界限制模型可用来源，不替代上述同步设置。清除本机记录也不等于删除云端、Git 历史或已经传给服务商的内容。
