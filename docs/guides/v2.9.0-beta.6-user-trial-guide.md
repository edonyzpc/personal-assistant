# Personal Assistant 2.9.0-beta.6 用户试用指南

> 适用版本：[`2.9.0-beta.6`](https://github.com/edonyzpc/personal-assistant/releases/tag/2.9.0-beta.6)，发布于 2026-08-02。
> 最低 Obsidian 版本：`1.11.4`。这是预发布版本，建议先在测试 vault 或已备份的 vault 中试用。

这次 Beta 的重点不是让 AI 更频繁地生成内容，而是让已有笔记在合适的时候自然
浮现，并让你在决定保存或修改前始终看得到来源、目标和预览。

## 这次最值得试的三件事

1. **拾页 · 深度发现**：从当前笔记出发，沿关联线索读取其它笔记，给出有来源依据
   的新发现；没有足够价值时会保持安静。
2. **从拾页继续到 Chat**：把完整洞察、来源和“为什么现在浮现”带进一段新对话，
   由你编辑问题并手动发送。
3. **把结论安全保存到笔记**：Chat 或拾页可以准备新建、追加、编辑和属性更新，
   但必须先显示内联预览，再由你确认；已完成的操作可在安全条件满足时撤销。

## 安装或更新

### 第一次通过 BRAT 安装

1. 在 Obsidian 社区插件中安装并启用 `Obsidian42 - BRAT`。
2. 打开命令面板，运行 `BRAT: Add a beta plugin for testing`。
3. 粘贴仓库地址：

   ```text
   https://github.com/edonyzpc/personal-assistant
   ```

4. 为了让本轮反馈可复现，请固定到 `2.9.0-beta.6`，不要只跟随滚动的 latest。
5. BRAT 安装完成后，进入 `设置 → 第三方插件`，启用 `Personal Assistant`。
6. 确认插件版本显示为 `2.9.0-beta.6`。

### 已经装过较早 Beta

在 BRAT 中更新 Personal Assistant，并再次确认版本号。若你之前固定在某个
`2.9.0-beta.N`，需要把目标版本改为 `2.9.0-beta.6`。

## 使用前检查

进入 `设置 → Personal Assistant`：

1. 在 `AI 与服务` 中确认 Chat 服务商、聊天模型和凭据可用。
2. 在 `功能 → 拾页` 中确认拾页已启用，并检查 `深度发现` 开关。
3. 在 `数据与隐私` 中检查数据范围；被排除的文件夹、标签或笔记不会进入深度发现。
4. 只有准备测试写入时，才开启
   `把对话和 Pagelet 建议保存到笔记（Beta）`。

关键默认值：

| 设置 | 默认行为 |
| --- | --- |
| 深度发现 | 新安装默认开启；旧安装可能继承此前“后台审阅准备”的关闭状态，请手动核对 |
| 写入能力 | 每个 vault 默认关闭，必须显式开启 |
| 建议保存有价值的结论 | 默认开启，但只在写入能力已开启时生效 |
| 写入审计包含笔记内容 | 默认关闭 |
| 写入审计保留时间 | 默认 30 天，可改为 90 天 |

Memory 不是深度发现的硬门槛。已准备的 Memory 可以提供额外线索；Memory 不可用时，
拾页仍可使用允许范围内的笔记读取工具。若启用了当前支持的 Qwen Web Search，拾页
也可能用网页资料验证已经从 vault 中发现的线索，但不会用网页内容代替 vault 作为
发现起点。

## 推荐试用路线（约 15–20 分钟）

### 1. 运行一次深度发现

先选一篇有一定内容、并且和至少一两篇其它笔记存在潜在关联的 Markdown 笔记。
过短或完全孤立的笔记更可能没有结果。

推荐入口：

1. 打开目标笔记。
2. 运行命令 `拾页：发现关联`；也可以长按拾页角色约半秒后选择 `发现关联`，或快速
   双击 `Control`。
3. 等待拾页完成探索。复杂探索可能经历多个模型回合，单次最长约 3 分钟。
4. 如果找到通过质量检查的新洞察，拾页面板会显示完整内容、来源笔记和“为什么现在
   浮现”。逐个打开来源，确认洞察是否真的被原文支持。

本 Beta 中，`审阅当前笔记`、`快速回顾`、`发现关联`、`打开相关回顾` 和
`打开范围回顾` 等既有入口已经统一到同一条深度发现管线。为了让反馈更容易比较，
建议本轮优先使用 `拾页：发现关联`。

没有出现洞察不一定是错误。当前质量门要求至少有当前笔记和另一篇仍在允许范围内的
笔记作为证据；如果关系只是表面相似、来源已经变化、内容不够新，拾页会安静结束。

### 2. 观察它是否在合适的时候浮现

开启深度发现后，拾页可能在这些自然时机安静准备结果：

- 离开刚才阅读的笔记；
- 编辑停止约 5 秒；
- 重新打开一篇发生过变化的笔记。

只有结果通过来源、时效、新颖度和提醒节奏检查时，拾页才会提示“有新发现”。点击
拾页，在 Bubble 中选择 `查看洞察`，再检查完整 Panel。重复看过的相同结果不会为了
证明功能正在运行而反复打扰你。

`功能 → 拾页 → 今日深度发现用量` 会显示本地当天的启动次数、模型回合和工具调用。
每天最多启动 36 次实际探索；缓存命中、越界拒绝或服务不可用不会计入。达到上限后，
自动触发会安静跳过，手动触发会显示提示，次日恢复。

### 3. 把拾页洞察带到 Chat

1. 在完整洞察 Panel 中点击 `在聊天中讨论`。
2. PA 会打开一段新 Chat，并显示 `来自 Pagelet` 附件。
3. 检查附件中的完整洞察、vault 来源、可用的网页来源、浮现原因和验证时间。
4. 编辑输入框里的简短问题，再由你手动发送。

这个动作不会自动调用模型，也不会自动写笔记。若 Chat 正在回答，或输入框已有其它
草稿，拾页会保留现状并拒绝覆盖。附件只属于当前会话；发送前关闭或重载 Chat 后，
需要从拾页重新打开。

### 4. 从 Chat 安全保存一条结论

先在 `数据与隐私` 中开启
`把对话和 Pagelet 建议保存到笔记（Beta）`，并使用测试笔记或现有测试目录。

1. 在 Chat 中围绕当前笔记或 Memory 完成一段有明确结论的对话。
2. 直接说出写入意图，例如：

   ```text
   把上面的结论保存到 0.unsorted/Beta 6 试用记录.md，先给我看预览。
   ```

   请确保目标父目录已经存在；当前 Beta 不会自动创建文件夹。
3. Chat 会显示 `审阅笔记变更` 卡片，列出操作类型、目标路径和内容预览。此时尚未写入。
4. 检查无误后点击 `确认变更`；不想继续则点击 `取消`。
5. 写入成功后立即测试 `撤销` 或 `全部撤销`，并确认笔记恢复。

一次提案可以包含新建、追加、编辑或属性更新。预览和撤销凭据只保存在当前运行内，
约 30 分钟后失效，插件重载后也不会保留。若笔记在预览后被其它操作修改，确认会
安全停止；若写入后笔记又发生变化，撤销也会停止，不会覆盖较新的内容。

当一段基于 vault 的对话形成明确结论时，Chat 还可能安静显示一次
`这条结论值得留在知识库里`。点击 `保存` 只是发起下一轮写入提案，仍然必须经过同样
的预览和确认；点击 `暂不` 后，本次对话不会再次提醒。

### 5. 测试拾页中的单笔记关联动作

开启写入能力后，完整深度发现 Panel 会提供类似
`在“当前笔记”中关联“来源笔记”` 的动作：

1. 点击关联动作，检查目标笔记和 `pa-related` 属性预览。
2. 点击 `确认` 后，PA 只给当前锚点笔记添加一条单向关联。
3. 点击 `撤销`，确认这次属性更新被恢复。

Bubble 中不会直接出现写入按钮；必须先打开完整、有来源的洞察。双向关联、多文件
修改或需要你判断的复杂动作不会在拾页中直接执行，应选择 `在聊天中讨论`。

## 安全与隐私边界

| 流程 | 可能发送给 AI 服务商 | 是否修改 vault |
| --- | --- | --- |
| 深度发现 | 当前锚点及探索中读取的允许范围内笔记；可选网页查询 | 否，深度发现始终只读 |
| 拾页 → Chat | 打开附件时不发送；你手动发送后，附件中的洞察与来源上下文会进入该次 Chat | 否，附件本身不授予写入权限 |
| Chat 写入提案 | 当前对话和为选择目标而读取的允许范围内上下文 | 只有点击确认后才写入 |
| 拾页关联动作 | 准备预览不调用第二次模型 | 只有点击确认后才更新一个笔记的属性 |

写入能力目前只开放新建、追加、编辑和属性更新；不开放重命名、移动、删除、文件夹
创建、任意 Obsidian 命令、Shell 或脚本执行。默认审计只记录操作类型、目标、状态和
时间等信息，不保存 prompt、模型回答、diff 或笔记正文。只有你显式开启
`在写入审计中包含笔记内容` 后，审计文件才会包含完整 before / after 内容。

## 建议重点反馈

- 深度发现是否真的带来了新连接，而不是复述或只说“这两篇相关”；
- 每条结论能否从列出的来源中核对，来源链接是否打开正确笔记；
- 它出现的时机是否自然：太频繁、太慢、太安静都值得反馈；
- 旧入口统一后是否更易理解，还是让你找不到原本想用的功能；
- `来自 Pagelet` 附件是否完整、清楚，并且没有覆盖你的 Chat 草稿；
- 写入预览是否让目标和影响一目了然；取消、过期、并发变化和撤销是否可靠；
- 桌面与移动端的拾页长按菜单、Bubble、Panel 和确认卡片是否容易点击、阅读和关闭。

## 常见情况

| 现象 | 说明或处理 |
| --- | --- |
| 手动运行后没有洞察 | 可能没有通过跨笔记、来源、新颖度或时效检查；换一篇关联更丰富的笔记再试 |
| 提示“深度发现暂不可用” | 检查 Chat 服务商、模型、凭据，以及模型是否支持当前所需能力 |
| 提示“不在 PA 当前允许的数据范围内” | 检查 `数据与隐私` 及拾页排除规则 |
| 达到今日 36 次上限 | 次日自动恢复；当前 Beta 不提供调高上限的设置 |
| 拾页关联按钮是禁用状态 | 在 `数据与隐私` 中显式开启写入能力；也可以继续使用 `在聊天中讨论` |
| Chat handoff 提示忙或已有草稿 | 等当前回答完成，或先发送/清空现有草稿，再重试 |
| 写入卡片显示已过期 | 重新发出明确保存请求，让 PA 生成一份新预览 |
| 撤销提示无法安全执行 | 目标在写入后又发生变化；PA 不会用旧快照覆盖新内容 |

## 反馈方式

请在 [GitHub Issues](https://github.com/edonyzpc/personal-assistant/issues) 提交反馈。
涉及私人笔记时，请只提供脱敏后的最小复现内容。

```text
版本：2.9.0-beta.6
Obsidian 版本：
平台：macOS / Windows / Linux / iOS / Android
入口：命令 / 拾页长按 / 自动浮现 / Chat 保存 / 拾页关联
预期行为：
实际行为：
是否可稳定复现：
截图或脱敏示例：
```

Beta 最有价值的反馈不只是“有没有报错”，也包括：它有没有在恰当的时候，让一条
真正有用、能回到原始笔记核对的旧想法重新出现。
