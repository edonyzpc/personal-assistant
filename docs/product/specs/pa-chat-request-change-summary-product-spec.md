## Problem And Product Outcome

同一次修改被工具批次拆成多个审阅对象，用户难以理解最终留下的变化与撤销范围。
目标是一次请求、一张结果卡、全部变化可查、一次确定性撤销入口，符合
[安静且可信](../pa-product-north-star.md)与[低审阅负担](../pa-low-burden-review-product-principles.md)。

## Scope

### In Scope

| Requirement | 行为 |
| --- | --- |
| B-178/REQ-01 | 同一用户请求的全部 Operations 批次与 SDK 子操作归入一张 Chat 卡片；不按模型阶段拆卡，不跨用户请求/会话/领域合并，纯阅读不创建修改卡片 |
| B-178/REQ-02 | 默认收起；展开查看全部真实变化。同一内容的连续修改展示初始到最终净差异；失败、跳过、未写入预览和已撤销部分不混作当前有效变化。断点保留分段说明；所有现有资源效果仍可核对 |
| B-178/REQ-03 | 同一入口撤销本次已发生且可恢复的修改，按真实效果顺序逆序，保留现有 owner 校验；重复点击/多视图不重复恢复，冲突、未知或不可恢复断点停止后续逆序恢复，真实报告已撤销与剩余范围 |
| B-178/REQ-04 | 完成/停止/错误后的单卡保留实际结果，区分部分完成、未知、撤销中、全部/部分撤销与不可用。执行未收敛时不开放整次撤销；全部撤销后差异默认收起并标为历史；停止不等于撤销 |
| B-178/REQ-05 | 操作按钮统一「撤销 / Undo」，进行中「撤销中… / Undoing…」；全部文案沿用项目中英文 UI 机制，用户内容不翻译；键盘、窄 Chat 栏、桌面与常规 mobile 可操作 |
| B-178/REQ-06 | 沿用会话内生命周期、来源/权限/身份与临时恢复期限；Chat/tab 同源状态，失效后无新写权限。无新增持久正文/差异/Undo、审计、provider 请求、设置或能力；Pagelet 和其他领域原合同保持 |

### Non-goals

- 局部接受、逐文件/片段 Undo、Redo、强制二次确认或强制打开 tab。
- 通用事务/依赖图/恢复平台、持久修改历史、跨重载/设备/用户请求恢复。
- 修改 Agent 拆分策略、固定工具次数、模型语义规则或自然语言完成判定器。
- 重做 diff 算法、Writing/Ghost/Memory、SDK 能力、Pagelet 或旧审计目录管理。
- 全主题/机型/语言笛卡尔测试矩阵、模型成功率/性能/成本研究。

## User Flow And States

1. Agent 正常分步执行。修改过程中只呈现简短实际进度，同一请求不新增批次 Review 卡片。
   已发生效果及时进入同一内存投影，不等待最后一句文字才能保留。仅预览清楚标为“尚未修改”，
   不激活 Undo；预览与实际效果在同一外层内分区，不能把预览内容计入已保存变化。
2. 请求结束或停止且 owner 效果已收敛后，卡片展示真实状态、笔记名/可辨路径与变化摘要。
   一般正文修改可写“已更新 N 篇笔记”；混合资源效果用相应结果，不把 editor buffer 或打开文件称为已保存。
3. “查看全部变更 / View all changes”在卡内展开所有笔记/资源的实际变化，不受 compact 截断；
   复用纵向 diff、增删标记、字词高亮和上下文。既有完整审阅 tab 保留为可选空间，同请求复用一页。
   展开/收起不执行笔记读写或调用模型，不丢失原操作事实。
4. 用户点击“撤销 / Undo”：界面立即显示撤销中并防重复；领域 owner 按逆序逐项恢复。
   不能跨过结果未知、不可恢复或校验失败的效果继续恢复更早步骤；已完成的恢复保持真实记录。
5. 全部撤销：显示“已撤销本次修改”，收起差异；“查看已撤销的变化”只看历史。
   部分撤销：显示已撤销和剩余事实，原始差异明确标为本次历史记录，不把每个 diff hunk
   强行对应为一个 receipt。冲突说明后续编辑已保留，不能误称已全部恢复。
   SDK 在请求中主动撤销也保留真实恢复事实；后续新修改仍进入当前变化。只有全部
   实际操作收敛且效果均已恢复时才显示全部撤销，用户首次整次撤销冻结当时的历史差异。
6. 后续用户消息属于新的请求与卡片；旧卡片不吸收新变化。当前 Chat 正在生成/执行修改时，
   既有卡片的整次 Undo 暂不可发起，避免恢复与新写入交错。关闭/切换源会话、reload/unload
   沿用原失效边界；不从历史记录恢复差异正文或 Undo 权限。

## Trust, Data And Authority

- 模型评估目标是否完成；UI 依据 owner 回执及实际运行生命周期展示事实，不根据最终答复关键词判成功。
- 连续快照有断点时不将人工变化归因给 Agent；撤销继续比较当前状态，不能用本次起点覆盖整篇。
- 二进制、附件恢复数据仍由原 owner 私有持有；审阅只引用既有元数据与允许的文字。
- 不扩大数据发送或持久化。Chat history 继续保留已有有限 action facts，不加入新正文快照。
- 不扩大任何工具权限；原生移动及反向移动仍由 Obsidian 维护引用。
- 每项实际效果及时可查，后续原生写入尚未收敛或停止后的结果未知时不开放撤销。
- 已知失败按结构化结果提供中英文说明；恢复期限过期不能声称“没有写入”，成功恢复
  后不保留旧失败说明。原始诊断继续留在原诊断链，不翻译用户内容或解析错误字符串判状态。

## Acceptance Criteria

| Acceptance | 通过条件 |
| --- | --- |
| B-178/AC-01 | 一次请求包含多个模型阶段/原生工具/SDK 子操作时只有一张卡；重复事件不增卡/结果，下一请求不合并；纯阅读无修改卡 |
| B-178/AC-02 | A→B→C 展示 A→C；撤销/失败/跳过不算当前变化；外部编辑断点 A→B、B′→C 不合并冒充纯 Agent 差异；多笔记、移动与既有非正文效果可查，完整内容无截断 |
| B-178/AC-03 | 同笔记跨批次 C→B→A 逆序恢复一次；人工后改、缺失/过期回执、撤权、未知效果与多视图竞态不造成越界/重复/跳过依赖恢复，部分成功如实保留 |
| B-178/AC-04 | 停止后保留已写入事实；执行中与未知不伪称完成；撤销后默认收起且历史标签准确；部分撤销/冲突不显示全部已撤销，未完成范围可辨 |
| B-178/AC-05 | 中文/英文的标题、展开、按钮及所有状态完整；按钮为「撤销 / Undo」，禁用时仍同名且原因可见；原文不翻译；320px 代表窄栏下长文案无溢出，键盘和 mobile 触摸入口可达 |
| B-178/AC-06 | 卡片/tab 同步、失效/迟到回调无新效果；历史重开不恢复正文快照/权限；既有 Pagelet/batch、SDK 资源恢复、审计退役、来源及 action facts 回归保持 |
