## Problem And Product Outcome

Chat 在已有大量来源时反复准备、检查，并可能阻塞整个 Obsidian。Debug 也通过来源 guard 干预记录，且重启后缺少 reasoning 和完整工具结果。目标是让 Agent 基于真实快照继续工作，配置变化只在后续 loop 生效，历史能解释实际全过程；符合“安静且可信”的低管理负担。

## Scope

| ID | Requirement |
| --- | --- |
| B-165/REQ-01 | 当前在途模型生成及其网络重试/fallback 沿用已接受输入；随后配置排除、原文件编辑、删除不令该响应或交付失效 |
| B-165/REQ-02 | 下一轮实际模型输入不再包含新排除的旧材料及其受影响派生内容；Agent 获得变化事实，自主更新取材，无固定附加分析轮次 |
| B-165/REQ-03 | `list_vault_tags` 等工具保留必要元数据统计；来源记录用于事实追踪与低频变化处理，不能形成持续全量授权检查；新读取按生效配置过滤 |
| B-165/REQ-04 | 同一轮无材料/配置变化时只准备一次；取消重复的阶段准备、发送前旧来源全量复核和逐片段来源复核，实际摘要或新模型尝试保留自己的输入与记账 |
| B-165/REQ-05 | Debug 开启后，完整文本输入、输出、provider reasoning、工具参数和结果写入设备本地历史；不因后续来源变化过滤，重启后仍可查看 |
| B-165/REQ-06 | Debug 保留现有期限、显式清理、凭据过滤与 vault/设备隔离；完整文本与提取内容落盘，媒体仅引用/类型/指纹。旧历史缺失如实标注，容量或存储故障不能伪称完整，不阻塞 Agent |
| B-165/REQ-07 | 准备、流式回复、完整 Debug 采集期间，原生 tab、编辑、保存、命令、Stop 可响应；不以降低任务能力、来源范围或模型输出预算换取响应性 |
| B-165/REQ-08 | 生成材料快照与实际动作目标分开；写入冲突、动作授权、防重复、独立图片任务、显式删除及取消继续由各自 owner 处理 |

### Non-goals

- 不重做整个 Host/Agent 架构，不引入通用权限缓存、Worker runtime 或第二个索引。
- 不调整 Memory 自动准备/marker、模型选择、任务预算、联网范围或费用策略。
- 不因本次标签扫描推导普通 Chat 必须调用 `list_vault_tags`；工具是否有用由 Agent 按任务选择。
- 不开展全产品扫描、全平台性能矩阵或额外遥测平台；不把方案当作修复、发布证据。

## User Flow And States

1. Agent 按任务获取当前允许的新材料，记录实际读到的版本/内容快照。
2. loop 消费尚未处理的来源配置变化：收起新排除材料及其派生上下文，提供变化事实给 Agent。
3. 准备一次本轮材料，必要的上下文裁剪/摘要后组装最终请求；开始这次模型生成。
4. 生成过程中配置或文件变化不回头修改这次请求、不丢弃它的内容。若有后续 loop，在下一轮处理配置变化；若本次直接结束，不自动另发一次请求。
5. Debug 观察实际输入、返回、工具、错误和变化事件，按顺序写入本地历史；不把旧记录再注入模型，也不由 Debug 决定回复是否有效。

| 变化 | 当前生成 | 后续 loop / 新读取 | Debug |
| --- | --- | --- | --- |
| 用户配置新排除来源 | 正常完成 | 移除新排除旧材料及其派生内容，按新配置取材 | 保留当时实际过程 |
| 普通正文编辑、文件删除/重命名 | 正常完成 | 已读快照不追溯撤销；真正再读时得到新内容或不存在事实 | 不以当前文件重写历史 |
| 用户主动 Stop | 取消当前工作 | 不自动恢复或新增请求 | 记录真实取消与已发生用量 |
| 明确删除 Debug/对话、Forget | 按对应操作既有语义处理 | 不因快照规则复活已明确删除的记录 | 清理队列、缓存、数据库，迟到写入不复活 |

“下一轮”是下一次 loop 构造实际模型输入，不把一次多轮 run 等同于一个永远冻结的请求。Owner 明确：网络自动重试和 stream fallback 仍属当前轮，配置改变后也沿用原输入，不提前应用下一轮的配置规则。每次物理请求仍如实记账、遵守取消与既有重试策略。

## Trust, Data And Authority

- 来源的当时事实与当前可取材范围分离；配置变化只在发生时处理受影响上下文，不把普通文件事件当成全量复核信号。
- 摘要、助手历史、工具调用参数也可能包含被排除材料；不能只删除可见引用或最初工具结果。无法可靠拆分的受影响派生段退出下一轮输入，由 Agent 决定是否补查；不删除用户可见 Chat 历史。
- Debug 扩大的内容仅在 Debug 已开启时采集，保存本机；保留原开关及可见缺失说明。完整文本/提取内容保存，媒体只记录引用、类型和指纹；原文件后来不可用时如实提示。
- 完整指实际可观察、实际发生的内容；不伪造 provider 未返回的 reasoning，不回填旧版本未保存的详情。现有凭据/认证材料不采集规则保持。
- 生成材料快照不授予写入、删除或发布权限；工具实际副作用继续遵循领域合同。

## Acceptance Criteria

| ID | Maps to | Observable outcome |
| --- | --- | --- |
| B-165/AC-01 | B-165/REQ-01 | 固定响应生成途中分别改配置、编辑/删除源文件，该响应正常完成；网络重试/fallback 仍用原输入，未因来源变化重组或丢弃 |
| B-165/AC-02 | B-165/REQ-02 | 配置变更后的下一轮 loop 实际输入不包含新排除正文、工具参数、摘要或派生答案；同轮重试仍用原输入；Agent 可根据变化重新取材，无变化无附加处理 |
| B-165/AC-03 | B-165/REQ-03、B-165/REQ-04 | 大范围元数据统计语义保持；相同轮次包装不增加材料准备次数；固定快照的发送与重试不再重验旧来源，也不以复制/序列化整份内部证据来证明它未变化；无取材配置变化时，旧来源完整复核不随 loop 或 chunk 增多，新增材料按当前生效配置准入 |
| B-165/AC-04 | B-165/REQ-05、B-165/REQ-06 | 一次含 reasoning、工具调用、失败或 fallback 的运行重启后，输入、输出、reasoning、全部实际工具结果仍可查看且次序正确；来源改删/排除不清掉过程 |
| B-165/AC-05 | B-165/REQ-06 | 老历史可读；未提供/旧版未记录/真实容量故障分别标记；显式清理与 Forget 无迟到复活；到期规则保持；提取文本持久化，媒体无额外本体副本 |
| B-165/AC-06 | B-165/REQ-07 | 无网络间隔的连续缓冲回复也能在消费过程中处理输入与 Stop；从准备到最终渲染、Chat 保存及 Debug flush，实际点击原生 new tab、切 tab、编辑落盘、命令和 Stop 均及时兑现，无长阻塞后集中回放。按同宿主空闲基线记录逐次操作发起至可见生效；Debug 开/关、大文本详情展开及最终保存合并在代表性场景验收，不以任务结束前最终操作成功代替响应性 |
| B-165/AC-07 | B-165/REQ-08 | 生成来源被改不误撤销生成；写入目标冲突、未知效果防重复、用户 Stop/明确删除及已接受图片任务的相关回归保持 |
