# 从 Pagelet 的发现继续思考 Product Spec

Document status: Approved
Updated: 2026-10-23
Work item: B-187
Decision: [DEC-072](../decisions/dec-072-pagelet-chat-continuation.md)
Authority: Owner 已确认的来源直达、阅读与继续输入体验；本轮仅设计文档，实施状态由 Tracker 承接。

## Problem And Product Outcome

把「发现 → 阅读依据 → 继续思考」衔接好：用户进入 Chat 后能认出刚才的发现，
按需打开依据或原笔记，再继续编辑和发送问题。稳定阅读由附件中的完整发现承担；
回到存活的原 Pagelet 页面是辅助便利。减少操作负担，不增加阅读任务、确认步骤或管理页面。

## Scope

- **B-187/REQ-01 — 继续思考优先**：保留「在聊天中讨论」、现有可编辑默认问题、草稿冲突保护和主动发送。
  附件始终有标题或原文内容线索；有待发送附件时隐藏通用空态问题，保留必要的 AI 配置提示。无需先阅读才能发送。
- **B-187/REQ-02 — 阅读一致**：待发送与按现有接受/保存条件生成的历史附件，都可分别展开来源和完整发现，
  默认收起，保持阅读动作含义一致；继承主题、限高和内部滚动，不要求外围布局同构。
- **B-187/REQ-03 — 来源直达**：原笔记独立展示，其他来源按真实路径/URL 去重，数量排除原笔记。
  使用已有材料，不生成引用证明或新增上下文。仅有原笔记时不显示空的来源展开项。
- **B-187/REQ-04 — 准确的辅助导航**：全文展开区底部可提供低强调的「在拾页中查看」，只定位存活实例内
  同一条、同一内容的发现，复用仍在的阅读状态。已知不可用时省略；点击后才失效则展开附件全文并说明事实。
  该项为次级便利：若接线成本扩大，可在 Tracker 明确后置，不阻塞核心。
- **B-187/REQ-05 — 阅读不扰动讨论**：展开和导航不清空或覆盖草稿、不发送消息，
  阅读/导航自身不主动发起或依赖重新发现及模型调用；已有后台发现仍按用户设置和现有策略运行，
  不新增抑制机制。保留来源/材料准入、会话生命周期及删除行为，用户下一步任务仍由既有 Agent 处理。

不纳入新的发现算法、coding 能力、自动摘要、来源版本管理、强制阅读、原笔记光标恢复、
全局导航历史、跨关闭/重启恢复（B-182）、Chat 异步恢复优先策略（B-183）、新埋点或权限流程。

## User Flow And States

沿用原生笔记/Pagelet 标签页与 PA Chat 布局。待发送附件示意如下，名称为虚构样例：

```text
来自 Pagelet                                      ×
先让用户获得一次成功
10 月 23 日 16:00 · 当时带入的发现
原笔记：下周计划 ↗

查看来源（2）⌄
展开完整发现 ⌄

[讨论这条 Pagelet 洞察，帮我判断下一步。]      发送
```

标题优先用正文已有标题，否则取原文首句或短段，不新增 AI 摘要或持久字段。
准备时间位于内容线索下，已有浮现原因放在完整发现展开区。「在拾页中查看」只放该区底部。
历史附件保留消息布局和生命周期，没有移除待发送上下文按钮；默认态同样能认出发现。

| 动作/状态 | 用户结果 |
| --- | --- |
| 查看来源、原笔记 | 打开正确的当前正文；先复用已打开目标，否则原生新标签，保留 Chat 和 Detail |
| 来源笔记不存在 | 提示「这篇笔记暂时无法打开」，不创建同名文件，不猜测替代来源 |
| 展开来源 | 笔记与网页使用已有链接；轻提示「链接打开当前笔记；此处保留当时带入的发现。」 |
| 展开完整发现 | 就地读完整原文与浮现原因，继承附件限高/滚动，输入区仍可用 |
| 辅助入口可用 | 选中原笔记下同一条、同一内容，不因路径相同打开最新发现；复用仍存的阅读位置/展开状态 |
| 辅助入口点击时失效 | 展开全文，提示「原发现已不可用，已展开当时带入的内容。」；不重建 Detail 或重新发现 |
| 移除待发送附件 | 沿用现有移除行为；无附件时恢复原空态，不覆盖已有草稿 |

不新建「返回 Chat」系统，使用仍保留的原生标签/面板继续输入。控件可换行、键盘及点击可达，
不依赖悬停；窄宽沿用现有面板布局，不引入独立移动方案。采用 Obsidian/PA 主题，不指定固定链接色。

## Trust, Data And Authority

来源链接不是逐条结论证明，也不是 AI 读取授权。笔记导航打开当前文件，附件表达当时材料；
不自动保存来源全文或建立来源版本库。点击已有网页沿用现有外链方式，不后台抓取网页。
handoff 正文、身份、接受校验、入模与历史保存边界沿用
[B-176](./pagelet-reading-loop-product-spec.md)；不扩大取消、失败或未接受材料的保存条件。

可视化依据是本对话 `pa-pagelet-chat-navigation.html` 的收敛版；早期 `pa-three-journeys.html`
不新增导航要求。绿色「已有」、琥珀色「待改」和编号是审阅注解，正式界面不显示。
原型只说明布局与局部交互，不证明源码、多个结果身份或真实应用验证已通过。

## Acceptance Criteria

- **B-187/AC-01**：从发现进入 Chat 能认出内容，可编辑问题并主动发送；已有草稿不被覆盖。
  有附件时没有通用空态问题干扰；移除后恢复适用空态，必要配置反馈保留。
- **B-187/AC-02**：来源与原笔记分别打开正确当前文件，缺失时不新建；会话、草稿与附件不变，
  长正文可读而不挤出输入区。
- **B-187/AC-03**：辅助导航纳入实现时，同原笔记多个结果仍命中当时同一条、同一内容；
  已存在的阅读状态复用，不被重新载入最新集合覆盖。
- **B-187/AC-04**：已知不可用时只保留稳定全文入口；若辅助导航点击后目标关闭、替换或不再可读，
  留在 Chat 展开全文并给事实提示；回退自身不主动发起或依赖模型调用，不新增恢复状态。
  辅助项后置时不保留无效按钮。
- **B-187/AC-05**：已接受材料随历史显示时，来源、原笔记与全文的阅读动作含义一致，
  不误改消息、不再次发送；导航不改变来源权限、材料验证和既有接受/保存条件。
