# Pagelet 自主发现闭环 Product Spec

Document status: Approved
Updated: 2026-10-16
Work item: B-175
Decision: [DEC-065](../decisions/dec-065-pagelet-autonomous-discovery.md)
Authority: 第一轮自主发现闭环的用户行为、范围及验收；获批目标不等于当前运行实现。

## Problem And Product Outcome

让 Agent 利用许可内容主动发现有用的旧内容、联系、当前笔记的问题及改进机会，并由
Pagelet 可靠呈现。深入发现不必等待额外点击；用户可以忽略提示、阅读来源或继续讨论，
不需要管理一条发现生产流程。模型决定内容价值，产品提供安静且可信的环境。

## Scope

- B-175/REQ-01：Agent 自主决定探索和交付，不以固定数量、来源数量、关键词、
  exact-ID、探索次序、首/次发现或相似度门替代模型判断；所有提示词和工具回执遵循同一边界。
- B-175/REQ-02：允许直接最终回答；保留可选的多份完整 Markdown 暂存，暂存后仍能继续。
  完整文本可包含多个发现；原文与每份来源/身份保持，不由 Host 拆解成语义类别。
- B-175/REQ-03：维持实际入模证据、来源身份/版本、许可范围、引用真实性和独立失效校验。
  单篇锚点足以支持的发现可以交付；结构校验不宣称证明结论正确。
- B-175/REQ-04：合格检索恢复与是否暂存无关；复用既有 query/lexical plan、run-scoped
  单次 token、策略及取消边界，恢复失败保留仍有效的原结果。额度不是洞察数量或探索深度上限。
- B-175/REQ-05：第一轮交付的全部有效文本与来源可读可达；显式“发现”实际启动分析，
  查看已有内容不暗中发起新分析。不再从来源排列推断 Link 主操作。
- B-175/REQ-06：如实区分完成、模型明确无发现、保留已完成结果但运行未完成、失败、取消、
  失效/撤销以及本次无新增可交付内容；不把异常、空输出或被规则拒绝伪装为“没有洞察”。
- B-175/REQ-07：沿用当前冻结 Vault 笔记、只读发现工具、provider/来源范围、
  调度/自动运行额度及副作用授权。发现修改建议不执行修改；交接不制造用户授权。
- B-175/REQ-08：自动结果以轻量可忽略提示交付，不抢焦点；只改完成闭环必需的界面接线，
  第一轮验收结束后停止扩张，后续入口和上下文方案单独讨论。

### Non-goals

- 全面改造短点/长按、已看内容复访、Detail tab / Save 旧流程；若其问题直接阻断本轮
  必需交付，仅修复该阻断，不把相邻模块全部纳入。
- 编辑器未保存文本、选区、编辑差量、跨轮历史、偏好记忆或新的洞察分类/质量评分系统。
- 专用修改建议 schema、自动应用、补丁预览系统、新权限或新的 Chat/Operations 流程。
- 改写共享 Memory 检索/索引算法、平台 rollout、一般 PA Agent 框架，或新建任务队列/持久恢复中心。

## User Flow And States

现有笔记事件或显式发现 → 既有真实准入 → Agent 读取与自主探索 → 可选完整暂存并继续
→ 最终回答或真实终态 → 按每份完整文本校验 → 全部有效结果进入现有展示与来源链路。

自动运行可直接形成深入洞察，也可只发现一个表述问题或明确无发现；不要求交齐某几类内容。
前台明确反馈运行结果；后台失败留内容无关的诊断并保持安静，不覆盖仍有效的旧成果。
部分成果可看时标明运行未完成。显式取消/权限失效不能以“抢救结果”为由绕过撤销。
纯查看仍使用已有查看入口；主动提示打开、滚动和来源访问不要求用户先再次分析。

## Trust, Data And Authority

许可内容可以发送到已配置 provider，沿用共享首次透明说明及既有设置；本轮不扩大外发、
网络或存储范围。已有 web 能力仍受实际 provider/capability 约束，不升级为通用联网。
暂存仅属于当前 run 的完整交付文本和来源，不保存内部推理或半成品；缓存沿用现有策略。

Host 核验实际到达模型的内容和来源版本；调用了某个读工具、返回了同名路径或模型声明
“已验证”均不等于来源证明。对当前笔记的判断必须有其实际内容依据，但不规定某个工具必须第一步调用。
来源撤销/变化、cancel、并发或过期回执仍可阻止接纳。独立文本独立失效，不在文本内猜测哪些段落可保留。

建议和探索保持只读。现有 Discuss in Chat 携带原文与来源供后续用户意图使用，不自动发送、
不覆盖既有草稿、不把洞察内容当执行指令。用户随后明确要求修改时，按当前 Operations
契约处理；本轮不增加写能力，也不回退为每次修改都要新的重复确认。

## Acceptance Criteria

- B-175/AC-01：代码和真实组装的模型输入均不包含被撤销的语义限制；已获得证据后仍可
  合法继续探索，既无指定工具路线，也无固定“足够了”门槛。
- B-175/AC-02：无暂存可完成；多次暂存加最终回答可保留超过旧上限的完整文本；
  一份包含多发现的 Markdown 不被拆分/截断。完成后的部分成果可在受控失败中保留。
- B-175/AC-03：锚点单来源交付有效；伪造、未实际入模、越界、版本改变和失效回执不被接纳；
  一个暂存文本失效不误删独立且有效的其他文本，所有交付来源可追溯。
- B-175/AC-04：none/partial 合格恢复无需暂存；同 run token、冻结查询、许可/currentness、
  取消及 standard fallback 均保留；恢复不产生额外发现数量或工具禁用门。
- B-175/AC-05：现有内容存在时，显式发现仍能发起新分析；查看不重跑。所有有效结果
  原文可读、来源可打开，来源排序不自动转成关联/修改主操作。
- B-175/AC-06：模型无发现与 error/cancel/incomplete/stale 等状态可区别；
  已消费调用仍计入真实用量，失败不冒充完成、不破坏独立的有效旧成果。
- B-175/AC-07：冻结快照、来源/provider 权限、自动准入、调用与效果边界保持；
  自动洞察不写笔记，交接不自动发送或代用户确认修改。
- B-175/AC-08：部署后能观察自动提示、显式运行、全文和来源、必要终态；
  没有自动打开完整面板或抢焦点。确定性、实际模型和实际 app 证据分别记录，
  不以模型必须找到指定发现或固定工具次数作为验收。

## Open Decisions

第一轮没有阻止设计的未决产品选择。后续轮次只是方向，不能据此派生本轮任务或测试门。
