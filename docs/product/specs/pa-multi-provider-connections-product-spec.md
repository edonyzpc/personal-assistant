# PA Multi-provider Connections Product Spec

Document status: Approved
Updated: 2026-10-30
Work item: B-192
Decision: [DEC-077](../decisions/dec-077-multi-provider-connections.md)
Authority: Owner 已确认的多连接、继承、Memory 保留及 OpenAI 图片行为契约；实施验收事实见最终验证记录，不代表版本发布。

## Problem And Product Outcome

用户配置一次默认服务即可开始使用，并能在已保存服务间切换而不反复改 Key。
某项能力缺失或有明确偏好时才单独选择；切回旧服务不会丢失已准备的笔记检索数据。
遵循“安静且可信”：可见的实际来源、按需展开、无隐式付费和无额外管理队列。

## Scope

### In Scope

- B-192/REQ-01 — 保存多条连接，各自拥有稳定身份、凭据引用、服务/地区/地址及模型选择；支持同服务多账号，用可读名称/序号区分，改名/换 Key 不丢配置。
- B-192/REQ-02 — 默认 AI 服务及聊天、笔记检索、图片三项继承/独立选择；例外不随默认切换，恢复默认后重新按默认解析，聊天覆盖不传染其他用途。
- B-192/REQ-03 — 首次 Chat inline 与 Settings 共用配置操作；简单路径仅服务/必要地区/Key，模型采用预设；用户无需理解或维护 ID/SecretStorage 名称，填写/替换/移除 Key 有明确操作；高级配置可达，保存与生效明确，失败保留草稿。
- B-192/REQ-04 — 能力/凭据/请求状态按用途准确展示；Key 已保存不等于联网验证；不被动探测密钥，不静默换服务/模型或复制其他连接 Key。
- B-192/REQ-05 — 所有文字 AI 工作使用解析后的聊天连接；保留可选 Policy 模型、现有 Agent/多模态契约与服务选项；独立笔记检索只覆盖准备/检索。
- B-192/REQ-06 — 切换时展示实际影响；目标 Memory 未准备时由用户主动准备，聊天可继续；已有首次使用及后续维护授权边界不被每连接首次放宽。
- B-192/REQ-07 — 按有效 embedding 配置保留独立数据及状态；另一配置的创建/失败/取消/重建不破坏旧份，切回兼容份复用，换 Key 不另建。
- B-192/REQ-08 — 非当前 Memory 不调用服务付费维护；切回核对当前笔记/排除范围，复用未变数据，增量处理变化，失效内容不得继续返回；沿已有维护授权。
- B-192/REQ-09 — OpenAI 和 DashScope 图片均覆盖文字生成、参考图创作、图片编辑；保留确切输入、原件、版本、数量、结果展示/导出/保存，模型参数按实际能力解释。
- B-192/REQ-10 — 请求固定实际连接/模型/来源；取消、配置变化、未知受理、重启和迟到回调保持真实状态，不跨服务重发；已提交图片归属原任务和服务。
- B-192/REQ-11 — 幂等迁移旧配置/凭据引用/图片偏好/任务/Memory；可靠来源才关联，未知归属保持数据并就地请求补充，迁移失败可重试且不假报成功。
- B-192/REQ-12 — 删除连接明确处理正在使用的引用及任务，不自动选择其他接收方、不连带删 Memory；显式 Memory 清理明确作用范围，不误删其他配置或用户笔记。
- B-192/REQ-13 — 凭据使用 SecretStorage，不进入普通设置、任务/聊天/日志；新存储名称简短且能辨认服务，不含完整 vault/连接 ID；由系统处理防重和引用，旧名称安全兼容。沿现有同步及设备本地 Memory 边界，不隐式增加服务、文件托管或代理设置。
- B-192/REQ-14 — zh/en、桌面和移动端保持一致的有效配置、返回/焦点/草稿与错误恢复；窄屏和键盘可操作，无需新增配置向导或多索引管理页面。
- B-192/REQ-15 — 服务定义与协议适配可通过代码扩展；协议复用不把所有服务冒充 DashScope，不以兼容 API 宣称 Agent 或全部能力已经可用。

### Non-goals

- 动态 provider 插件安装、自动服务故障转移、价格路由、负载均衡、自动发现/测试所有模型。
- Memory 全部 AI 处理独立化、索引跨设备同步、后台同时维护多个模型、自动回收旧份。
- 新图片编辑器、蒙版/图层 UI、公共图床、额外 Files API 托管、跨设备图片任务同步。
- 重写主 Agent、图片任务平台、VSS 后端或凭据系统；更改 Ghost 等非本范围连接。
- 发布、执行付费模型验证、替用户修改现有真实凭据或迁移私人 vault。

## User Flow And States

1. 新用户在 Chat 或 Settings 选择服务及必要地区、填 Key 并保存；采用对应模型。
   未知凭据状态仅在已有明确动作中读取，普通展示不探测。
   连接自动命名为“OpenAI”“OpenAI 2”等，可改为“工作”“个人”；重名由系统
   补可读序号并在保存前展示，界面不出现内部 ID。Key 状态使用“已配置/未配置”等
   真实事实，提供“填写/替换/移除”；留空或取消替换不删除已保存 Key。
2. Settings AI 概览突出一个默认服务，三项实际服务/模型为结果摘要，不要求逐项配置。
   “按功能调整”默认收起；继承项显示“跟随默认”，独立项始终显示“单独使用”和
   实际连接，提供“恢复默认”。即使独立连接恰好等于当前默认，也保留独立语义。
3. 切换默认、单独选择和恢复默认均先编辑草稿，就地显示实际变化及 Memory 影响，
   明确应用才生效，不再叠一层通用确认。未准备时提供“准备 Memory”，不是后台开始。
   从用途添加连接时明确“保存并用于该用途”；提交前取消不创建连接、不改绑定。
   管理入口“保存连接”只保存。跨存储部分失败如实说明，不假称已全部撤销。
4. 切回兼容 Memory 时先核对本地数据，未变部分复用。存在变化时准确区分可用内容与
   待更新部分；不能把旧片段描述为当前笔记事实，也不阻塞普通聊天。
5. 图片沿现有单一 CreateImage 流程。改变连接/模型后不沿用不兼容参数；本次选择
   不改全局偏好。状态以请求、受理、生成、保存的真实事实推进。
6. 功能失败就地说明原因并指向该用途的修复入口，保留仍有效的请求草稿和返回位置；
   没有图片能力不使整个 AI 配置“未完成”。“Key 已保存”是中性事实，未联网验证
   不成为每行警告或常驻测试待办；Memory 检查、准备、部分可用和恢复失败使用不同操作。
7. 删除正在引用的连接时说明受影响用途，用户在该操作中选替代或取消；不隐式回落。
   删除连接不会清除其 Memory；清理另有明确范围。删除后焦点回到仍存在的连接或
   添加入口，普通保存/返回不自动打开已经离开的详情。

界面状态、草稿和恢复规则见 [Settings当前架构](../../architecture/settings-status.md#current-summary)。

## Trust, Data And Authority

- 笔记原文是源数据；各模型检索数据属于设备本地派生数据。切换不自动删除派生数据。
- 笔记准备/查询发给笔记检索服务；对话及必要检索片段发给聊天服务；图片描述和明确
  输入图发给图片服务。来源型生图的文字准备继续用聊天连接，只传已授权素材。
- 首用披露及有成本准备确认沿已有契约。配置服务的信任不授予额外数据范围或未知受理重试。
- UI/Agent 不读取或选择原始 Key、任意 endpoint；实际服务由配置 owner 解析，任务留非秘密来源。
- 连接显示名、内部身份与密钥存储引用分开。新存储名以服务前缀及短防重后缀生成，
  无需用户输入；改显示名不移动密钥。旧长名先保留关联，用户明确替换 Key 时可采用
  新名称；不为美化名称被动读取/搬迁全部密钥，不承诺宿主列表中的旧名立即全部消失。
- 移除 Key 保留连接和 Memory；共享或未知归属的旧槽不被清空，但本连接必须解除对
  它的使用，不能借缓存或兼容回退继续调用。另一设备缺少新引用对应凭据时明确补填。
- 部分成功保留可用结果，旧数据和笔记不被另一配置的失败清理；不承诺远端取消或本地缓存永不丢失。

## Acceptance Criteria

| ID | 可观察通过条件 |
| --- | --- |
| B-192/AC-01 | 保存 DashScope/OpenAI 及同服务第二连接，用可读名称区分，来回选择后 Key 引用、各模型不串；改名不移动密钥，改名/换 Key 不造新 Memory |
| B-192/AC-02 | 三项分别验证继承、独立、恢复默认；独立项在收起调整区后仍可辨；恢复默认先预览再应用，聊天单独改服务不改变另两项 |
| B-192/AC-03 | Chat 与 Settings 首配均可完成；草稿零请求/零生效；从用途新增取消零写入，保存只作用明确范围；失败保留仍打开的草稿、不假成功或假报全部撤销 |
| B-192/AC-04 | 服务无能力、PA 未适配、模型不支持、凭据未知/缺失/读取失败、401/限额/网络错误有准确状态及局部修复；正常未验证无警告待办，无隐式 fallback |
| B-192/AC-05 | Agent 工具、文字辅助调用和 Policy 使用正确聊天连接；笔记准备/查询使用独立选择；检索结果按原来源边界进入回答 |
| B-192/AC-06 | 切换到无数据配置后 embedding 请求为零；用户主动准备才调用；新连接不绕过确认，真正 first-use 与已授权增量维护保持原契约 |
| B-192/AC-07 | A 准备→B 准备→A→B 在重载后仍保留各份；B 失败/取消/重建不改变 A 的数据库和准备事实；兼容切回不全量重算 |
| B-192/AC-08 | 非当前配置无付费维护；切回仅处理必要变化，删除/排除/改动旧内容不被当作有效命中；授权不足不后台更新 |
| B-192/AC-09 | 两服务的生成/参考/编辑产出真实图片；旧版本可分支，数量不暗减，原件/透明处理按能力，复制/下载/保存及来源型生图保持 |
| B-192/AC-10 | 在途切换、改 Key、删除、停止、重载、未知受理、迟到完成不串连接/会话/索引；无重复物理提交；已受理图片恢复只查询/保存原任务 |
| B-192/AC-11 | 旧单连接、独立 Wan、设置与旧索引不一致、凭据归属未知、跨存储失败/重启均保留原数据并可重试；重复迁移无副本膨胀 |
| B-192/AC-12 | 删除引用中的连接无暗换服务，取消零删除；删连接保留 Memory；移除 Key 保留连接/Memory且不恢复旧凭据，留空替换零删除；清理仅作用指定范围 |
| B-192/AC-13 | Key 不出现在普通持久化/日志/Agent 数据；普通UI无ID管理，新存储名简短可辨服务且占用不覆盖；旧名迁移失败保留引用/值，设备缺凭据不借用；协议仍可在受支持平台执行 |
| B-192/AC-14 | zh/en、320px 窄屏、200% 文本、键盘/触摸、返回焦点/滚动/草稿与错误重试通过实际交互 |
| B-192/AC-15 | 新服务代码接入只需明确服务定义及必要适配；已知能力与真实请求协议一致，未验证 Agent 能力不被宣称已支持 |
