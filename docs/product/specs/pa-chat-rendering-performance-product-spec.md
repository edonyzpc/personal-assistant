# Chat Rendering Performance Product Spec

Document status: Current
Updated: 2026-10-18
Work item: B-180
Decision: [DEC-070](../decisions/dec-070-chat-rendering-lifecycle-performance.md)
Authority: 本文持有 B-180 已实现的四项 PA 侧渲染优化及兼容、生命周期边界。Owner 于 2026-10-18 授权开发、定向修复和验证，随后明确要求收尾 B-180 并提交本地 master；验收证据见文末历史记录，发布另行授权。

## Problem And Product Outcome

删除一轮历史会重建剩余消息，恢复历史会连续构建大量正文；无关的状态栏观察和 Mermaid
稳定循环又增加显示后的工作。目标是减少 PA 发起的重复工作、给历史恢复期间的输入和
阅读留下响应机会，符合[安静且可信](../pa-product-north-star.md)的产品标准。
原生单次渲染和必要布局仍会发生，不用缩减内容或改变原文换取性能。

## Scope

### In Scope

| Requirement | 行为 |
| --- | --- |
| B-180/REQ-01 | 删除历史轮次后，未变化消息保留既有 DOM、owner 和原生交互；只清理被删除轮及确需更新的附属 UI，历史、上下文和领域业务副作用保持现有语义 |
| B-180/REQ-02 | 完整恢复会话数据后分批恢复历史显示，批次之间让出主线程；全部消息最终按原顺序出现，恢复期间可以继续发送，旧批次不得覆盖新回复、复活被删除消息或写入其他会话 |
| B-180/REQ-03 | PA 正文的无关 DOM 变更不再触发状态栏子树扫描；真实状态栏的挂载、替换、移除、样式和尺寸变化仍正确更新底部避让 |
| B-180/REQ-04 | Mermaid 稳定后不持续主动逐帧请求布局修正；有界窗口内迟到 SVG/尺寸变化仍可处理，用户暂停自动滚动和退出清理继续有效 |
| B-180/REQ-05 | 保留原生 renderer、B-179 显示兼容、链接/嵌入/代码/图片/Mermaid 与后处理能力；原文、复制、完整上下文、持久历史、权限和现有流式调度不变，无新增设置、provider 请求或迁移 |
| B-180/REQ-06 | 分别验证减少重复渲染、分批响应机会、观察范围和稳定工作次数；记录真实环境与未消除的原生/布局成本，不把计时窗口当作纯布局或首个可交互时间 |

### Non-goals

- 表格流式子树复用、尾部解析、通用 DOM diff、虚拟列表、Worker 或替换 Obsidian renderer。
- 裁剪历史/媒体、改变消息显示宽度或样式、重构领域任务和确认/撤销流程。
- 保证单次原生构建可抢占、固定 60fps、固定提速比例或所有设备上总耗时缩短。
- 新增用户可见性能开关、常驻采集系统、跨会话 DOM 缓存或私人会话测试夹具。

## User Flow And States

1. 删除仍使用现有入口、确认及生成中限制。确认期间会话或对象发生变化时，沿用现有
   身份复核；成功删除后剩余消息可继续复制、打开链接、阅读 Thinking 与附属卡片。
2. 重开或切换会话时，历史数据先就绪，显示按批次出现；不会等待全部历史绘制完才允许
   发送。新消息保持在历史之后，后续恢复批次不会把旧内容追加到新回复后面。
3. 保留现有初始滚动意图；批次和迟到布局修正尊重用户主动向上阅读，不反复强制到底。
   空会话、失败终态和中途关闭沿用现有含义，不新增加载弹窗或错误静默吞掉路径。
4. 桌面与现有 mobile 共用功能与完整内容。重开视图、清空和卸载会使旧显示任务失效，
   已失效的原生异步结果不得再发布。

## Trust, Data And Authority

- 原始消息仍是复制、存储、后续 Agent 上下文与原文操作的来源，显示进度不是数据边界。
- 保留删除既有的 Operations discard 和领域上下文注销语义；显示复用不制造新的效果、
  权限、任务取消或恢复授权。图片等仍由既有领域 owner 管理。
- 无新增外发、AI 费用、持久状态或确认。会话中模型文本仍只作为待显示内容。
- 回滚渲染调度与复用接线即可恢复旧路径；不回写或迁移用户笔记、设置和历史。

| B-180/AC-06 | 同类合成夹具在已部署 test vault 对比前后调用次数、连续主线程工作/帧间隔、完成时间和观察/稳定工作次数；桌面及官方 mobile 交互验证与性能样本分别记录，不以单样本给出普遍提速承诺 |

## Implementation And Lifecycle Contract

当前实现位于 [LLMView](../../../src/chat/chat-view.ts)，回归由既有
[Chat suite](../../../__tests__/chat-view.test.ts)承载：

1. 历史恢复与实时回复转历史两条路径，均以现有 `HistoryTurnEntry` 对象登记轮视图。
   局部删除只失效、卸载目标轮；菜单、图片与 Thinking 资源走既有清理入口，保留其余
   正文、buffer 和 owner 身份，并更新新尾轮的 source decision 操作及当前 `result`。
2. 领域 owner 继续负责持久删除、上下文重置、Operations discard 和图片/Writing/Ghost
   注销。局部删除在全会话 discard 后清理已经失效的 Operations 卡及其资源；Clear/New
   等待持久写入时保留禁用卡的原时序不变，DOM 复用不创造新的取消或 Undo 权限。
3. 完整数据先恢复，再以 view 局部 epoch 分批创建消息与发布正文。当前软预算 8ms、
   每批最多 8 个任务、最多 4 个原生在途；单次原生不可抢占，满额后任一完成即可继续。
   用真实帧/任务边界让出，不串行等待整条异步后处理，也不先创建全部消息壳。
4. 固定历史插入边界保持旧消息位于新回复之前；每个恢复 epoch 捕获一次 sourcePath，
   后续批次及分享保留该路径。轮 membership、会话/epoch 和 render token 共同拒绝过期
   发布；同会话新发送不取消有效历史。图片目标登记完毕后只加载一次，删除最后待登记
   目标也会触发就绪检查，旧任务快照不能复活已删除轮的卡片。
5. 新恢复在首批前仅一次初始化自动跟随并清除旧滚动意图；后续历史批次及迟到 Markdown/
   Mermaid 修正均尊重本次恢复中的用户暂停。恢复开始时的尾部 Mermaid 观察资格独立于
   强制滚动，不因分批显示丢失迟到尺寸观察。
6. 状态栏观察以已登记正文 buffer 身份快速排除内部变更和整体替换；涉及真实状态栏或
   其挂载位置的记录仍走既有检测，不忽略整个 Chat，也不新增布局读取。
7. Mermaid 获得尺寸样本后以 0.5px 阈值、3 次稳定计数停止主动帧；原 4000ms 窗口内
   保留 ResizeObserver 与增强通知，迟到变化只请求合并修正。无 ResizeObserver 保留有界
   fallback；轮删除、重置、关闭和卸载释放 owner、观察、菜单、帧及定时器，旧异步结果
   仅清理自身，不能写入新 epoch。预算参数可校准，不是帧率或耗时承诺。

无本范围未完成项。若必须改变原生内容能力、媒体、权限或持久化边界，按 DEC-070 的
重议条件提交具体取舍；表格流式子树复用仍由 B-179 的独立候选边界约束。
