## Problem And Product Outcome

用户明确要求同时移除笔记中的图片及其实际附件时，不能仅完成笔记编辑后宣称
全部完成。一次审阅应覆盖两项影响，保护其他笔记并支持恢复原文件和原文。

## Scope

- B-160/REQ-01：针对用户明确选中的笔记图片和实际本地附件准备联合操作，支持
  Featured Image callout 及普通图片嵌入；目标由实际引用解析，不靠文件名猜测。
  预览展示完整笔记变化和附件影响，保留 callout 中无关文字。
- B-160/REQ-02：首个写入前发现其他笔记或当前笔记剩余引用时，阻止联合删除并
  提示冲突。必要核查不可用、不完整或不获准时停止；不宣称已经证明无引用。
- B-160/REQ-03：沿用来源、文件身份、版本和写入权限；当前明确联合删除请求可直接
  执行，不再整批二次确认。仅讨论/准备预览、取消或关闭审阅页不触发删除。
  使用官方文件接口按 Obsidian 设置删除实际附件。
- B-160/REQ-04：分别报告笔记与附件效果，区分等待确认、完成、部分、确定失败
  和未知。提供获准的原操作只读状态核查，保留历史事实，不自动重提或续写。
- B-160/REQ-05：支持当前有效 Undo 窗口的一键恢复，先恢复附件再恢复笔记原文。
  本次实际字节和笔记恢复快照必须在首个写入前准备好；漂移、碰撞、实际准备失败、
  失效或未知结果不能被忽略，不能覆盖用户后来创建或修改的文件。
- B-160/REQ-06：临时二进制仅在领域内存中保留，有统一归属、到期和执行中资源
  管理；不发送模型、不进入 Chat history/Debug/审计/持久目录。恢复能力不跨重载
  或设备。复用公共 Obsidian API，平台限制必须明确验证或报告。
  移动端默认用 Obsidian CLI mobile simulator 验证；只有涉及 iOS 系统特有能力或
  已确认模拟器无法覆盖的系统边界，才要求 iPhone 真机证据。

2026-10-05 Owner 撤销自设 Operations 数量、内容及恢复额度的硬拒绝要求。
合法操作及完整效果回读不因这些内部阈值被阻断；真实资源使用可提示，真实准备
失败须如实报告。后续 B-161 已完成相关源码移除与新验收；旧 B-160 验收保留原范围，
不倒改为新合同测试结果。

### Non-goals

- 任意文件或目录删除、全库孤儿扫描、自动附件清理、修改共享引用笔记。
- 永久备份、跨重载/跨设备恢复、恢复旧 audit 目录或重新引入完成度账本。
- 图片重新生成、未另获授权的真实 provider 付费调用、私有 vault 部署、Git 或发布。

Owner 已于 2026-10-05 授权使用 repo test 的公开夹具进行真实文本模型验收；
仅覆盖本特性的最小必要语义，不调用图片生成、不扩大到私人笔记。

## User Flow And States

Agent 理解用户当前明确选择，领域解析目标并准备实际联合操作，再核查引用、权限和
版本，准备恢复快照，按顺序修改笔记、删除附件。仅要求预览时不执行；目标/来源/范围
歧义先澄清，超出已有授权或已接受费用范围时说明变化并确认，不重复已获授权。
首笔写入前的冲突保持两个目标不变；首笔之后的变化停止后续效果并报告部分结果。
用户可在有效窗口内一键撤销，领域先核对并恢复附件，再原子核对并恢复笔记。
附件已恢复而笔记恢复失败时保留恢复检查点，不重复创建附件或伪称全部撤销。

## Trust, Data And Authority

只处理当前明确选择的实际目标。引用保护尊重现有 Data Boundary，不发送其他
笔记正文、禁止身份或二进制给模型。无法完成必要核查时不给隐式例外。
公开文件删除接口遵循 Obsidian 设置；临时快照过期或能力失效后，不保证可恢复，
尤其不能对永久删除设置承诺存在回收站副本。
执行和撤销只经有效的运行请求/领域能力发起，模型参数与历史收据不制造权限。

## Acceptance Criteria

- B-160/AC-01：选中图片的实际附件与笔记 diff 在同批审阅/结果中清楚展示；歧义、同名
  图片或包含其他内容的 callout 不造成错误目标或无关内容丢失。
- B-160/AC-02：预先存在的其他引用及必要核查不完整时，笔记和附件均零写入；
  变更后才出现的冲突停止附件删除并保留已发生的笔记效果。
- B-160/AC-03：仅准备预览、取消、失效和重复执行不新增删除；准备后目标替换、权限
  撤销或版本变化不删除错误文件；明确请求无二次确认，Markdown 原子检查保持。
- B-160/AC-04：笔记成功而附件失败/未知经过 UI、原操作查询、历史和模型投影
  仍准确；只有两个要求的效果均有 owner 事实才报告全部完成。查询零变更。
- B-160/AC-05：正常一次撤销恢复附件原字节及笔记原文；快照准备失败时零写入，
  碰撞与漂移不覆盖；部分撤销保留步骤事实，再次处理不重复已恢复效果。
- B-160/AC-06：正确管理预留和保留快照，过期及失效释放资源，执行中资源不被
  提前释放；卸载/重载不恢复能力，二进制不进入持久记录或 provider 输入。
