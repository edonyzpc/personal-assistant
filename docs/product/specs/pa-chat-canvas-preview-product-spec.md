# Chat Canvas Preview Product Spec

Document status: Current
Updated: 2026-10-23
Work item: B-184
Decision: [DEC-073](../decisions/dec-073-chat-canvas-preview-native-open.md)
Authority: 本文持有 Owner 于 2026-10-21 确认的 Chat Canvas 产品范围、用户行为和验收标准；2026-10-22 Owner 明确要求按 B-184 方案完成全部开发测试，后续选择“预览跟随原生解析，原始 JSON 原样保存”，并在审查修复请求中明确图片渲染不应受准入拦截。两次选择分别替代旧文字路径规则与图片展示限制，见 DEC-073；不追溯改判旧验证结果。2026-10-23 Owner 授权收尾及本地 master 提交，当前实现与历史验收分别进入 Architecture 和紧凑验证记录。

## Problem And Product Outcome

- User problem: Chat 中的 JSON Canvas 仅显示代码，用户无法直接读图，且手工保存后
  才能进入原生 Canvas；后续再次打开还需要避免与原生手工编辑混淆。
- Product outcome: Chat 直接呈现图文画布，用户按需修改保存路径，一次「保存并打开」
  进入新标签页的原生 Canvas；后续复用文件与标签页，Chat 保留生成时快照。
- North Star fit: [安静且可信](../pa-product-north-star.md)。忽略预览不制造文件，
  真实点击明确产生保存效果，原始回复与用户后续编辑都保持可辨认、可检查。

## Scope

### In Scope

| Requirement | 行为 |
| --- | --- |
| B-184/REQ-01 | 显式 `canvas` / `jsoncanvas` 代码块按 JSON Canvas 结构校验；普通 `json` 仅在结构可严格确认为 JSON Canvas 时增强显示。不得按关键词、标题或仅有 `nodes` / `edges` 键识别，也不擅自要求规范允许可选的顶层字段同时存在。保留原消息、原始 JSON 和复制语义，其他 JSON 继续正常显示。 |
| B-184/REQ-02 | 预览表达 `text`、`file`、`link`、`group` 四类节点及边的布局、方向、标签和分组关系，不静默丢弃内容。文件节点保留宿主既有笔记、图片、PDF 等本地嵌入能力，不缩为 Markdown-only；网页显示 URL 卡片而不自动抓取网页。文字中的相对引用跟随原生 Canvas 解析规则，不以拟保存目录重新定义其含义。保存完整原始 Canvas 数据及合法扩展字段。 |
| B-184/REQ-03 | Chat 预览可平移、缩放、适应窗口、选字和查看原始 JSON；打开入口是明确按钮，拖动、选字、缩放、节点及卡片交互均不隐含保存或打开。桌面、移动触摸与键盘可完成主要操作，适配实际 Chat 容器。 |
| B-184/REQ-04 | 预览与流式生成不自动写文件；内容完整且可保存后，首次真实点击「保存并打开」使用当前可见、可修改的默认 `.canvas` 路径完成保存和打开，不增加必经第二次确认。路径限于当前 vault，校验和内容准备未通过时不写入；无关同名文件不被覆盖。 |
| B-184/REQ-05 | 使用真实 `.canvas` 文件在新标签页交给原生 Canvas，获得当前宿主支持的完整交互；后续复用同一文件，已有标签页则激活它。明确绑定的已有 `.canvas` 直接打开，不另存；文件身份来自实际绑定与核验，不从模型文件名、标题、相同文本或某个文件节点猜测。 |
| B-184/REQ-06 | Chat 原消息和原始 JSON 保持不可变；「生成时预览」固定 JSON 中的节点位置、文本、边及引用，文件节点仍引用现有文件，不创建笔记或附件历史副本。当前 owner 按 REQ-08 图片例外与非图片边界保留已展示内容与交互，原生编辑后不主动重绘；重开时重新核验引用，重读内容标明「引用内容为当前文件」。保存后关联稳定产物并打开文件最新内容，原生编辑不反写消息，旧快照不覆盖文件。正确处理已核实重命名、删除及失效关联；删除聊天不删除已保存文件，恢复聊天不自动重建文件。 |
| B-184/REQ-07 | 复用 B-181 的稳定身份、view-local 交互状态、独立 owner、held 与「查看最新」策略，保持原生 Markdown 及其媒体和后处理兼容。无关更新不重建预览；流式输入、隐藏、切换、关闭和卸载均尊重既有发布与清理边界。 |
| B-184/REQ-08 | UI 预览、保存与原生移交不自动扩大模型来源、Agent 权限或 AI 费用。按 2026-10-22 Owner 的图片展示例外，实际当前 vault 的本地图片（含排除目录）及宿主支持的远端/内嵌图片正常原生渲染，text、file 图片节点、group 本地背景和获准嵌入笔记内图片规则一致；不按 Markdown 图片语法差异决定是否显示。远端图片可产生原生图片请求，UI 展示不形成模型 source grant。笔记正文及非图片资源仍在展开前检查共享 Data Boundary，拒绝时仅占位、不泄露新增事实，不借用已结束 run 的 guard。网页节点仍显示 URL 卡片，不自动抓取网页正文或展开 iframe；移交后的 file / link 由 Obsidian core 处理。普通 UI 保存复用公开 Vault API，不伪造 Agent Operations、授权或回执；原生 Undo 由 Obsidian 承担。 |
| B-184/REQ-09 | 数据、资源、保存、关联持久化与打开失败分层反馈，保留原始内容和已确认效果；仅重试缺失步骤，未知效果先核实原操作。持久关联采用必要字段、版本与身份校验，旧记录和无效记录可安全回退；恢复不得重放写入或打开，也不序列化权限、DOM、回调及运行期 owner。 |

### Non-goals

- 在 Chat 内重建完整 Canvas 编辑器，或把编辑后的文件双向同步回历史回复。
- 以模型或后台任务自动保存每张预览；扫描文件名或内容来猜测、覆盖已有产物。
- 自动抓取网页正文、自动向模型发送被预览文件，或新增 AI 请求、付费处理及跨 vault 权限；原生图片加载按 REQ-08 的明确例外执行。
- 为普通 UI 文件创建新增 Agent Operations、统一 PA Undo 或独立通用产物 runtime。
- 替换 Obsidian Markdown renderer、裁剪其他消息能力，或扩大 B-181 的恢复与设备范围。
- 把交互原型当作真实 Obsidian、原生 Canvas 或已部署插件的验收证据。

## User Flow And States

1. **生成与识别。** 回复中的显式 Canvas 块或可确认为 JSON Canvas 的普通 JSON
   获得预览。内容尚不完整时显示生成状态并保留原文；不能把半段 JSON 当成可保存
   产物。普通非 Canvas JSON 不受影响，结构错误不静默修复为另一张图。
2. **尚未保存。** 卡片标注「生成时预览」，可看图、平移缩放、选字并展开原始 JSON。
   卡片同时显示拟保存路径和「保存并打开」按钮；默认目录遵循 Obsidian 新文件位置
   规则，文件名取自画布标题，用户可在首次保存前修改。原型的 `Canvas/` 仅为示例，
   不隐含新增目录创建或设置。点击以外的浏览交互不落盘。
   Canvas 文字中的相对引用跟随原生 Canvas 解析规则，不随拟保存目录切换；嵌入
   笔记内部仍使用该笔记自身路径。修改目标仅影响本次保存位置及按宿主规则依赖
   Canvas 位置的文件引用。路径暂时无效时暂停依赖该路径的读取，保留原始 JSON 与
   画布视角；不为迁就目标目录改写保存内容，也不以原生链接更新补做首次引用转换。
3. **保存并打开。** 内容及目标核验通过后，一次真实点击创建完整 `.canvas` 并在新
   标签页打开；处理中不因重复点击重复创建。内容未就绪、路径无效或与无关文件冲突
   时，原预览保留并说明需修正之处。已有实际绑定文件则直接进入打开分支。
4. **原生编辑。** Obsidian Canvas 承担完整的平移、缩放、卡片与连接编辑、分组及
   当前宿主可用交互。原生编辑和 Undo 沿用宿主行为；Chat 不承诺对文件创建提供
   PA 统一 Undo，也不把原生效果伪装成 Agent Operations 的结果。
5. **返回与再次打开。** Chat 仍显示生成时快照；已保存状态显示文件关联及「打开
   Canvas」，明确打开文件当前内容。再次打开不覆盖编辑、不另建文件；文件已开时
   复用标签页。原始 JSON 始终属于原回复，与后续文件内容可区分。
6. **文件变化与失败。** 已核实的重命名更新关联；文件删除、关联无效或实际文件不符
   时说明现状，不自动重建或覆盖。保存成功但打开失败时显示已保存路径，重试只打开；
   关联写入失败或效果未知时保留已确认事实，先核实原操作，不把未知当成未保存。
7. **阅读连续性。** 各设备使用同一产品语义并按容器适配。用户操作变化正文后沿用
   held 和「查看最新」；任务进度继续。切换、隐藏与关闭不重置无关状态、不抢焦点，
   旧异步结果不得发布到其他消息或会话。

## Trust, Data And Authority

- Source evidence: 预览来自对应消息中的原始 JSON，或实际绑定的已有 Canvas。
  模型给出的路径、标题与自述均不等于文件身份或用户授权。文件节点的内容仅用于
  UI 显示，不因此进入 Agent 的已读来源或后续模型上下文。图片按 REQ-08 的原生
  展示例外处理；PA 展开笔记正文或非图片资源时，先按当前共享 Data Boundary
  检查路径、文件及实际内容边界；拒绝时
  只显示占位，不附加新读取的存在性、内容或其他文件事实，也不依赖已结束的 Agent
  run guard。原消息已有引用仍按原文保留，不能以占位为由改写原始 JSON。
- Snapshot semantics: 生成时快照的历史事实是原始 JSON 所含的节点位置、文本、边与
  引用，不是全 vault 或附件备份。当前 owner 内按 REQ-08 图片例外与非图片边界保留已展示
  的引用内容与交互；原生
  编辑不主动重绘 Chat。重开后重新核验并读取的引用内容属于当前文件，须明确标注，
  不能冒称生成时历史；原始 JSON 本身仍固定。
- Data sent / stored: 本功能不新增 AI provider 请求。远端图片由宿主正常请求加载，
  不代表向模型发送图片，也不自动抓取网页正文；非图片嵌入及原生移交继续使用各自
  既有资源规则。原生移交后属于
  Obsidian core 行为，PA Agent 来源控件不会自动约束其文件与链接加载。历史仅保存必要的
  产物关联和可校验元数据；原始消息保持原样，运行期权限与 UI 对象不持久化。
- User disclosure / confirmation: 可见路径和「保存并打开」明确告知此次点击的本地
  文件效果，一次点击即可完成，不再重复确认。真实路径、完整内容和执行结果由普通
  UI 保存 owner 核验；公开 Vault API 的拟接线属于 Proposed 软件设计，不是模型权限。
- Reversibility / recovery: 不覆盖无关文件或原生编辑，不随聊天删除文件。原生编辑
  Undo 归 Obsidian；不承诺 PA 的创建 Undo。失败只恢复缺失步骤，历史恢复不重新保存
  或自动打开。涉及新来源、网络、媒体或权限边界时，按 DEC-073 的重议条件处理。

## Acceptance Criteria

| Acceptance | 通过条件 |
| --- | --- |
| B-184/AC-01 | 显式 `canvas` / `jsoncanvas`、有效普通 Canvas JSON、普通非 Canvas JSON 及错误输入各走正确分支；结构识别不靠标题或关键词，也不增加规范外必填字段。原消息、原始 JSON 与复制内容逐字保持，错误不被静默改写。 |
| B-184/AC-02 | 代表性画布同时包含文字、文件、链接、分组和边；其布局、标签、方向及关联完整可辨。笔记、图片、PDF 等宿主已有本地嵌入保持对应语义，不能以只显示 Markdown 通过；网页仅显示 URL 卡片。Canvas 文字相对引用在预览与首次原生打开中遵循同一原生解析规则，在相同 vault 状态下指向同一资源，不随拟保存目录切换；嵌入笔记内部仍按笔记自身位置解析。保存后的 Canvas 保留全部原始节点、边、引用及合法扩展数据。 |
| B-184/AC-03 | 桌面、移动布局与键盘可使用预览平移、缩放、适应窗口、原始 JSON 和打开按钮；选字、拖动、缩放与卡片操作不触发保存或切换标签页。预览位置与展开状态不会被无关更新重置，操作内容可见、可达。 |
| B-184/AC-04 | 在尚未保存状态修改默认路径后，保存目标及按宿主规则依赖 Canvas 位置的引用重新核验，旧目标的迟到结果不发布；文字相对引用继续跟随原生解析，不改用拟保存目录。点击固定实际保存目标，不借路径变化改写原始 JSON 或重置画布视角。只有一次真实「保存并打开」点击才创建该路径的完整 `.canvas`；生成中、单纯预览、无效路径、内容未就绪和无关重名目标均不产生意外写入。流程无需第二次必经确认，连续点击不重复创建。 |
| B-184/AC-05 | 新保存和真实既有文件均能在原生新标签页打开，并实际操作当前宿主支持的卡片、连接、分组、缩放及编辑 Undo；再次打开复用同一文件与已开标签页，不写回旧内容。模型文件名或内部 file 节点不能冒充整张画布的已有文件绑定。 |
| B-184/AC-06 | 原生编辑后返回 Chat，原消息、原始 JSON 及其节点布局/文本/边/引用不变，当前 owner 按 REQ-08 图片例外与非图片边界保留已展示内容和交互，不主动重绘；再次打开保留文件最新编辑。重开预览重新核验的引用内容明确标为当前文件，不产生笔记/附件历史副本。运行期重命名沿真实文件更新，删除/替换后不误用旧文件对象；跨重启以记录路径重新核验并显式打开当前位置有效 Canvas，不能承诺追踪离线改名或永久文件身份。缺失时不猜测目标、覆盖或自动复建；删除聊天不会删除产物，历史恢复保留可校验关联。 |
| B-184/AC-07 | 无关刷新与同文输入不重建预览或其 owner；正文 held 后任务进度继续，仅「查看最新」应用待显示内容。隐藏、会话切换、关闭和卸载后没有旧结果发布或遗留资源；已有 Markdown、链接、嵌入、媒体、Mermaid 及原文操作保持兼容。 |
| B-184/AC-08 | 内联、引用块/多行定义等原生图片语法正常展示；当前 vault 中被来源排除的图片、图片 file 节点和本地 group 背景不因 Agent/Data Boundary 准入而隐藏，获准嵌入笔记内同类图片规则一致。远端/内嵌图片保留宿主加载能力；实际目标为笔记或其他非图片时不能借图片语法豁免。非图片路径、文件或正文被排除时不展开，只占位且不泄露新增事实；边界更新/历史恢复仍检查，不依赖结束的 run guard。UI 展示不进入模型上下文、不新增 provider 调用或 Agent 能力；网页节点不抓正文、不展开 iframe。普通保存仍依据真实点击与当前 vault 目标，不伪造 Agent 授权/Operations/回执；原生 file / link 及 Undo 由 core 处理。 |
| B-184/AC-09 | 数据/资源失败、保存失败、保存成功但关联失败、保存成功但打开失败及效果未知均反馈正确阶段；已成功部分不重放，未知效果先核实。旧记录、无关联、错误版本及失效关联能校验并安全回退，恢复不会自行创建或打开文件，也不恢复运行期权限、DOM、回调或 owner。 |

## Open Decisions

拦截；本次据此修订 REQ-08/AC-08，范围和取舍见 DEC-073 的图片展示修订。此前
