# DEC-072 — 从 Pagelet 的发现继续思考

Decision ID: DEC-072
Status: Accepted
Updated: 2026-10-24

Work item: B-187

## Context

PA 已支持 Pagelet 阅读、来源、Discuss in Chat、完整材料交接及接受后的聊天保存。
`43050df2` 的 Chat 待发送和历史附件仍把来源显示为文本，用户核对依据、回到原笔记后
继续输入有摩擦。B-187 解决这一段体验，不重做发现能力、Agent 执行或阅读历史。

目标是「发现 → 阅读依据 → 继续思考」，符合 [North Star](../pa-product-north-star.md)
的安静且可信。收益是减少查找和切换成本，不宣称提高发现质量或模型推理能力。

## Options Considered

| 选择 | 收益与代价 | 结论 |
| --- | --- | --- |
| 只在附件增加来源链接 | 接线少，但收起后可能认不出发现，仍缺少稳定全文入口与输入衔接 | 补齐最小阅读呈现后一并采用 |
| 来源、返回发现、原笔记三个平级主操作 | 导航明显，但返回常受原页面存活限制，抢占继续输入的注意力 | 不采用 |
| 来源直达、内容线索、附件全文；原页查看为次级便利 | 复用现有材料与页面，不增加管理负担 | 采用 |
| 建立发现历史和跨关闭恢复 | 提供更长期返回，但超出当前问题并增加状态与存储 | 本轮排除，B-182 保持独立 |

## Decision

1. P1 核心是来源与原笔记直达、可辨认的发现内容线索和继续输入。默认收起来源与全文，
   全文随时可展开；有待发送附件时隐藏通用空态问题，保留必要配置提示与草稿保护。
2. 原笔记从附件 anchor 取得，来源从已有真实路径与 URL 取得。笔记打开当前正文，
   附件保留当时带入的发现。打开笔记复用已打开的目标，否则用原生新标签，不替换 Chat 或 Detail。
3. 「在拾页中查看」仅作为全文展开区底部的低强调入口。只定位存活 Detail 内同一条、同一内容；
   已知不可用则省略，点击时失效则保留并展开附件全文。无需永久历史、持续监听或重新生成。
4. 待发送与历史附件保持阅读动作语义一致，沿用 PA 主题和现有限高滚动，保留各自外围布局。
   导航不覆盖草稿、发送消息或扩大来源权限；导航自身不主动发起或依赖重新发现及模型调用，
   已有后台发现仍按用户设置和现有策略运行。原有 handoff 校验与保存条件保持。
5. 辅助导航能小范围接通则一并实现；若实际成本扩大，可明确后置，不阻塞核心。
   不强绑原子交付，不引入新标题协议、旧无 hash 附件兼容或全量模型/设备测试矩阵。

2026-10-23，Owner 在计划审查后明确确认第 4 条的调用边界；仅收敛文档，
不新增后台发现抑制机制，不扩大设计和测试范围，不修改产品代码。

## Consequences And Revisit Trigger

本决定补充 [DEC-066](./dec-066-pagelet-reading-loop.md) 的 Chat 阅读衔接，沿用
[DEC-067](./dec-067-pagelet-note-detail-tabs.md) 的按笔记 Detail 和
[DEC-071](./dec-071-pa-ui-state-rendering.md) 的状态边界。无需改变材料格式、设置、存储或 provider 协议。
跨关闭/重启恢复、原笔记光标、全局导航历史、自动摘要和强制阅读不纳入本轮。
只有具体使用证据表明附件全文与原生页面不足以支持继续思考，才重新讨论更宽导航能力。
