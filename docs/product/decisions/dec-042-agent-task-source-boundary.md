# DEC-042 — PA Agent 取材边界与可调整计划

Decision ID: DEC-042
Status: Accepted
Updated: 2026-09-24
Authority: Owner 于 2026-09-23 先确认取材声明与 Host 准入方案，随后明确改为 Agent 遵循自由语言取材指令、Host 不作相应硬拦截；后述修订优先于原决定。
Work item: B-146

> **当前决定以最后一节 Owner 修订为准。**下文原方案及随后被替代的敏感外发分层保留为设计演变记录；自由语言限制作为 Host 硬上限、首次结构化取材声明及按该声明拦截读取的要求已被替代。已交付范围和验证限制见[当前 Product Spec](../specs/pa-agent-task-source-boundary-product-spec.md)与 [B-146 validation](../../archive/2026/b146-agent-task-source-boundary-validation.md)。

> **2026-09-24 后续目标决定：[DEC-043](./dec-043-agent-runtime-evolution-and-source-scope.md)。**Owner 已另行接受三种显式问答范围及实际输入/派生上下文的硬约束，局部替代本文“不增加本轮硬范围控件”的未来边界；这不是模型声明授权，也不重启敏感外发分层。自由语言职责、显式 Writing、Data Boundary 和独立动作保护继续有效。新设计见 [B-149 Product Spec](../specs/pa-agent-runtime-evolution-product-spec.md)，尚不改写 B-146 的已交付行为。

## Context

B-135 选择主 Agent 理解任务，由 Host 守来源和执行边界；B-144 选择任务完成导向的自主恢复。本次 Obsidian Chat 事故中，普通咨询的 `declare_source_scope` 因模型把中文引号改为英文引号而得到 `invalid_instruction_quote`，整个取材批次未执行，最终无进展并显示 `incomplete`。已检查的 [实现](../../../src/ai-services/task-source-constraint.ts)仅证明引文在传入文本中逐字且唯一出现，不证明声明的 `notes`、`webAllowed` 符合用户意思；[现有测试](../../../__tests__/task-source-run.test.ts)也能在用户文本为“只用当前笔记”时提交更广的 `vault` 范围。当前同一 run 的已提交范围只能收窄，使 Agent 的初步计划变成不可扩大的上限。

这暴露的是取材计划、用户限制和执行权限的职责混合。用户希望 Host 尽可能自动处理正常纠错，不被频繁确认打断；真正需要修改用户明确限制或承担新的实质后果时才交用户决定。

## Options Considered

| Option | Benefits | Costs / risks | Disposition |
| --- | --- | --- | --- |
| 只修复引号、格式或重试次数 | 改动小 | 保留“逐字匹配当授权证据”和首次计划锁死；误放行仍存在 | 不作为完整方案 |
| 完全由 Agent 自行决定取材及失败回退 | 灵活 | 若连独立设置、用户确认和副作用事实也交给模型，无法守住真实执行边界 | 仍不采用此无保护版本 |
| 用户边界与 Agent 计划分离；Host 按模型声明的用户上限准入 | 让 Agent 随证据调整 | 模型声明可能误解用户原话；声明协议还能误拒、阻断任务 | 原选择，已由后续 Owner 修订替代 |
| Agent 直接决定普通取材与搜索；Host 只守独立运行时保护 | 去掉声明协议和 Host 对自由语言的第二次裁决 | 自由语言取材限制不再有 Host 独立硬保证；仍需守住现有设置与副作用边界 | **后续 Owner 选择的方向；当前职责见 PA Agent architecture** |
| 每次来源变化都请用户确认 | 边界可见 | 频繁打断，不符合低负担产品方向 | 不采用 |

## Decision

1. **两层范围**：本轮用户明确限制及既有设置、排除、撤销、Data Boundary 等形成执行上限；Agent 首次声明的是可调整取材计划。计划可在上限内随证据修订。笔记、网页和工具结果不能成为放宽用户边界的授权。
2. **自然语言三分规则**：明确排他/禁止（如“只用当前笔记”“不要查网页”）是本次取材的硬边界；“尽量以当前笔记为主”等偏好由 Agent 优先遵循，必要时可用其他已获准材料并如实说明来源；看起来有限制但范围无法判清时先在确定获准范围内推进，只有必要目标确需更广取材才询问一次。
3. **真实执行保护**：Host 在每次物理读取/发送前重验当前用户边界和独立权限；不合规批次零新增读取。模型声明、引文或来源内容本身不授予权限。个人画像、既有 Memory、已授权风格及获准历史仍按 DEC-034/B-135 的独立用途与治理准入处理。
4. **低打扰恢复**：形状、参数、模型转写、暂时失败及 Agent 自设计划过窄等，在现有授权内自动纠错或改路。Agent 不自行降低必需目标、扩大用户边界或把部分结果称作完成。只有完成目标确需修改用户明确限制、承担未获准的实质后果或关键用户判断时，保留任务并给出一次具体选择；同一阻碍不循环追问。用户决定后在安全状态中继续。无用户可操作的解法时如实说明未完成。
5. **真实结果与交付**：普通咨询直接交付普通回答；来源准入失败不得误显示为写作恢复。等待用户、部分完成、技术不可用和已完成保持不同状态。恢复与重载仍遵守 DEC-040：同次插件运行可继续，重载后由用户选择继续，不自动重放未知副作用。
6. **语义证明边界**：产品要求明确限制生效，但不声称 Host 能从任意自然语言中形式化证明语义。逐字引文不是证明；技术方案必须区分真实用户文本与应用附加指令，提出可验证的限制识别、含糊处理和跨 provider 验收。此处 provider 验收按不同模型的行为计算；`deepseek-v4.1-flash` 与 `qwen3.8-max` 是两条模型路线，共用百炼服务入口不取消其模型差异证据。若达不到已确认的低打扰与来源承诺，须带证据重议，不得静默降低承诺或增设每轮确认。
7. **2026-09-23 意图判定职责校正**：Owner 指出把“只用当前笔记和它链接的复盘”截成“只用当前笔记”是词面规则越权做语义判断。用户自然语言中的排他、偏好、含糊、否定和组合范围由主 Agent 理解并结构化声明；Host 不用中英文关键词、正则或部分短语推断这些意图并生成新的硬限制。Host 只从明确的结构化权限、用户已作出的本次选择和实际文件身份/动作做确定性准入。字面路径可用于找文件身份，但其出现不代表读取授权或排他限制。声明形成边界后，Host 仍逐次硬性执行，不让笔记或工具输出扩权。语义误判风险以真实模型对照、实际读取记录和有界澄清验证，不伪称词面规则能证明用户意图。

### 后续 Owner 修订：Agent 自主取材，Host 不硬拦自由语言限制

Owner 在复核上述实现的剩余风险后，接受以下产品取舍；本节覆盖原决定中与之冲突的条款，不追溯改变原方案的验证事实：

1. 主 Agent 直接决定普通任务要读哪篇笔记、是否搜索、何时补查以及怎样依据实际结果回答。用户在消息中写出的“只用当前笔记”“不要联网”等自由语言取材要求由 Agent 遵循；Host 不再将其解释、模型自报的 `userBoundary` 或 `declare_source_scope` 作为普通读取的硬门。相应地，不再宣称 Host 对自由语言限制提供独立硬保证。需要确定性硬限制时，已有设置继续生效；是否增加本轮控件及其形式仍待决定。
2. Host 保留可从运行事实和明确权限核实的保护：真实文件与来源身份、已关闭能力和 Data Boundary 等结构化设置、实际读取/发送记录、取消与预算、已确认撤销或排除、重复及结果未知副作用。Agent 的计划、引文、笔记或工具输出不能伪造这些权限与执行结果。技术协议错误应让 Agent 在现有权限内恢复，而不成为普通取材的额外许可步骤。
3. 写文件、改配置、删除等持久或破坏性操作，以及发送受保护内容到额外外部服务等有实质后果的动作，先展示具体目标、内容和后果，由用户作本次决定后执行。正常笔记读取与已开启的常规搜索不逐次确认。已配置 Chat provider 的普通取材沿用用户配置时建立的基础信任；网页搜索等额外服务是不同目的地。
4. 该修订只确认产品方向，不授权将现有未提交 B-146 代码作为新方案交付，也不授权 commit、push 或发布。现有 Product Spec、SDD 和 Tracker 的原方案验收需按新目标重评。

### 前次 Owner 修订：额外外发的敏感信息边界（已被下节替代）

Owner 选择选择性保护：Host 依据用户明确标记的受保护内容和已有设置排除作硬保护；Agent 判断未标记内容是否敏感，若要向额外外部服务发送敏感信息，应在发送前主动请求用户决定。常规已开启搜索不逐次确认。此选择接受未标记内容可能被 Agent 漏判的剩余风险，不宣称 Host 能自动发现所有敏感信息。

受保护标记的具体形式、设置排除能否由本次决定临时例外、确认覆盖一次请求还是本任务中的同类发送，尚未决定。模型自报敏感性可触发主动询问，但不能代替 Host 对明确标记和设置的执行检查。

现有 Data Boundary 排除文件夹/标签是跨 Chat 等功能的完整来源排除：默认不可读、不可引用、不可发往已配置 Chat provider，只有既有显式本次例外流程可改变。这种排除不能直接充当“Chat 可读、但发往 WebSearch 等额外服务前需确认”的标记；是否为后一类内容增加独立标记是待决产品问题，不得通过重新解释现有排除设置来实现。

若增加后一类标记，Host 只比较外发文本与受保护笔记原句不足以兑现硬保护：Agent 可将已读内容改写为搜索词或其他工具参数。标记内容进入任务上下文后，额外外发的准入范围、派生内容及跨轮上下文如何处理，须在设计中明确；在此之前不能声称新标记的外发保护已可执行。

### 最新 Owner 修订：Chat 可读即允许用于已启用的模型和搜索

Owner 明确：一篇笔记只要按现有来源设置允许 Chat 读取，Agent 就可以按任务需要把它用于已配置 LLM 和已开启的 WebSearch 等 Chat 工具。Host 不再区分“Chat 可读但不可发往额外服务”的第二层内容权限，不增加对应的受保护标记、敏感性分类、派生内容追踪或逐次外发确认。前两节中要求发送受保护内容到额外服务时另行确认的部分，以及上节的选择性保护方案，均由本节替代。

现有 Data Boundary 排除仍是完整来源排除：默认不可读、不可引用，也不得进入模型或搜索工具输入。Data Boundary 产品规格描述了显式本次例外，但当前 Chat 运行时没有相应 UI/执行接线；旧 `request_source_decision` 不能充当这一例外。B-146 保持当前排除硬门，不以本次取材重构附带实现新的排除例外；若未来另行交付允许 Chat 读取的例外，该来源才适用同一 Chat 工具流转规则。WebSearch 开关、真实来源身份、取消/预算和写文件、改配置、删除等持久或破坏性操作的独立保护继续有效；Chat 可读本身不授予这些操作权限。Agent 仍应遵循用户自由语言要求，只向工具发送完成任务所需的内容，并如实说明实际来源。

这一选择接受的剩余风险是：允许 Chat 读取的笔记可能含有用户认为敏感的信息，Agent 可能把相关内容或改写内容放入搜索请求；Host 不作额外语义拦截或确认，不能承诺阻止此类发送。用户若要确定性禁止某篇笔记进入 Chat 工具流，应使用现有 Data Boundary 排除或关闭相关能力。

B-146 当前范围不增加本轮结构化取材控件：自由语言取材要求由 Agent 遵循，现有 Data Boundary、能力开关和独立操作权限构成确定性运行边界。将来若需要独立的本轮硬限制，应作为新的产品选择提出，不作为本次交付的隐含前提。

### 2026-09-24 Owner 补充：写作由显式 Chat 操作触发

普通咨询不应因为 Chat 常驻提供 Writing 能力而被模型交付为写作作品。写作采用与
`@CreateImage` 相近的显式入口：用户选择 `@Writing`，或在已有写作版本中明确
选择继续后，本轮才提供写作上下文与作品交付能力。普通 Chat 无论答案长短，均
不自动创建写作请求；写作关键词、前一轮作品和模型对问题的自行分类也不隐式
开启此能力。已保存的旧作品、恢复记录和重试应保持可读、可继续，不把历史
写作事实反推成新一轮普通问答的权限。此补充只调整 Writing 入口，不改变上述
Agent 自主取材、Data Boundary 或独立操作权限。

### 2026-09-24 Owner 补充：任务未完成的显式结果

来源被 Data Boundary 拒绝是确定性的读取事实，但不单独证明整个用户任务无法
完成。普通最终答复继续按实际执行结果交付；只有 Agent 明确报告无法完成时，
本轮才因任务结果进入 `incomplete`。为避免 Host 再用中文或英文关键词猜测最终
答复的语义，运行时提供可选的结构化纯输出标记，供 Agent 附上面向用户的未完成
说明。未使用该标记的普通文本不能仅凭措辞由 Host 重分类；模型漏报仍是验收与
后续改进的边界。来源授权撤销、预算耗尽、传输故障等独立运行失败仍按原规则处理。

### Relationship to existing decisions

后续修订替代 DEC-034/本决定中普通任务的前置取材声明要求，以及 DEC-040 中以该声明恢复来源阻碍的路径；保留主 Agent 负责语义理解、Host 负责独立权限和真实结果的职责。DEC-037 的基础工具自主规划、既有写入确认、Memory 治理、WebSearch 开关与付费/未知副作用边界继续有效。本轮“不要发送某类背景给模型”的首次请求前数据发送限制仍按 B-135 现有结构化输入边界处理；扩大该能力须另作产品决定。

## Consequences

- Product behavior: Agent 按用户自由语言要求自主取材与补查；来源指令由 Agent 遵循，不宣称 Host 独立硬保证。普通技术错误不制造确认负担；高后果动作需要具体用户决定。
- Architecture / data / safety: 去掉普通取材的模型自报上限准入，保留明确设置、真实文件身份与实际来源记录，以及写入和未知副作用等独立保护；Chat 可读来源可用于已启用的模型与搜索，不新增基于内容敏感性或目的地的 Host 外发门。
- Compatibility / migration: 不改变已有笔记、Memory、图片、作品、历史或设置数据的意义；旧会话与重载规则须验证。
- Work created or removed: B-146 原方案本地实现与验证成为历史证据；当前 [产品规格](../specs/pa-agent-task-source-boundary-product-spec.md)与[架构](../../architecture/pa-agent-architecture-plan.md#task-source-and-writing-output)承担稳定合同，[B-146 validation](../../archive/2026/b146-agent-task-source-boundary-validation.md)保留最终证据与限制。本决定本身不证明发布。

## Revisit Trigger

- 支持的真实模型反复违反用户自由语言来源要求，且来源透明或有界纠错无法满足用户信任。
- 来源变化必须引入新的外发、持久授权或跨重载自动续跑边界。
- 真正的用户伤害、资料外泄、显式限制被突破，或可观察确认负担明显超过收益。
