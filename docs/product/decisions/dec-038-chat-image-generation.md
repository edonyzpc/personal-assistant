# DEC-038 — Chat 内置图片生成、编辑与统一图片连接

Decision ID: DEC-038
Status: Accepted
Updated: 2026-09-18
Authority: Owner 于 2026-09-18 在方案讨论中逐项选择 A / 1，确认下列十项产品选择，并明确要求将讨论落成详细方案设计文档。当时授权范围为设计文档；后续实施与合成素材调用的独立授权及结果统一见 Tracker，不包含 commit、push 或发布授权。
Work item: B-133

## Context

用户希望在 PA Chat 输入 `@CreateImage` 和图片描述，直接得到可复制、下载的图片，
并获得类似 ChatGPT 的连续创作体验。当前 Featured Image 将笔记内容转换成配图并
插入笔记；现有 Chat 支持图片理解、文件保留和图文保存，但不能据此宣称通用生图已交付。

本决定承接 [DEC-030](./dec-030-multimodal-chat-image-copywriting.md) 留给 B-133 的
图片生成方向。它新增按需创作能力，不改变 PA 的
[North Star](../pa-product-north-star.md)：入口安静、用户主动调用、结果可忽略，
不自动制造配图，不用 AI 画面替代用户真实笔记或经历。

## Options Considered

| 选择 | Owner 已确认 | 未选择方案 / 取舍 |
| --- | --- | --- |
| D01 连续编辑 | 首版包含生成后的文字连续改图 | 不采用仅文生图的首版；增加确切输入和版本关系 |
| D02 Provider | 首版使用 Wan，覆盖现有两个图片模型的适用能力 | 首版不同时接入 OpenAI；优先完成闭环 |
| D03 连接 | 可独立配置图片连接，也可复用兼容的聊天连接 | 不强制跟随主 AI 连接 |
| D04 触发 | `@CreateImage` 与明确自然语言均可触发 | 不要求首次生图必须输入命令 |
| D05 后台 | 生成期间可继续文字聊天、切换会话；结果回原位置、不抢焦点 | 不采用等待生图结束后才能继续聊天的交互 |
| D06 存储 | 生成原文件进入 `pa-images` 聊天图片管理 | 不默认把全部试稿写成普通笔记附件 |
| D07 输入 | 支持用户主动上传、粘贴、从 vault 选择的参考图和编辑原图 | 不限于编辑 PA 自己生成的图片 |
| D08 数量 / 成本 | 默认一张，明确要求可多张；不自主增加付费生成次数 | 不固定每次只能一张，也不后台多次试图择优 |
| D09 恢复 | 有任务身份时恢复原任务 / 结果保存；不确定时不自动重新提交 | 不限于应用连续运行；不承诺无证据的恢复 |
| D10 统一连接 | Chat 与 Featured Image 共用图片连接与底层接入 | 不建立两套独立图片连接设置；两处参数与保存方式保留 |

## Decision

上述产品范围为 Accepted。首次选择 A 对应 D01，后续九次选择 1 依次对应 D02–D10。
记录确认结果，不把技术草案、接口尚未验证的能力或未讨论的参数默认值标成用户批准。

1. 主 Agent 理解需求、选择已授权图片、准备参数；宿主执行费用、来源、连接、
   取消和结果真实性边界。不用关键词/阶段工具门替代语义规划。
2. 图片生成、参考生成与编辑的结果均保留独立文件；修改不覆盖输入或旧版本。
   每张结果支持预览、复制图片内容、下载原文件和指定后续编辑。
3. 生图的持久任务独立于当前 Chat 视图。应用重启恢复只查询已受理任务或继续保存，
   不能把未知受理状态变成一次新付费调用。主动停止不在重启后自动恢复。
4. 只使用当次意图及既有来源规则允许的数据。首次透明说明图片服务、费用和存储；
   用户明确请求后不重复进行普通生图确认。更多数据、数量或高后果动作按实际边界处理。
5. 沿用聊天图片的原件保留、显式清理、同步状态说明和正式附件迁移规则。
   下载到设备、保存到 vault 和保存为笔记是不同动作；删除聊天不自动删除原文件。
6. 统一图片连接迁移保留已有 Featured Image 配置对应行为。Chat 当次参数不覆盖
   Featured Image 默认值。其笔记提炼、路径和插入方式保留；本决定不把 Chat 的
   后台插卡及重启恢复语义扩展为重启后自动向笔记插图。

Owner 对后续两个实际数据边界补充选择：

- **R-14 透明编辑输入：先说明，再确认。** Wan 不接受透明输入时，任务在物理提交前
  暂停，说明透明像素和白底副本的影响。只有用户明确确认该任务制作白底副本后才
  继续；原图与已有版本不变。拒绝或未确认不向 Wan 发送该图。不能把此前为一次
  合成素材端点验证单独授权的白底处理当作产品默认授权。
- **R-16 删除聊天：只留图片文件。** 删除会话或对应消息时，删除该内容所属的
  生成任务、操作绑定、版本关系、提示词与输入引用等生成元数据；停止本地交付，
  不删除已保存的图片原文件或正式笔记附件。删除后不再展示该任务的生成来源详情
  或恢复其编辑版本链。图片管理所需的通用文件记录仍按现有文件生命周期处理。

Owner 后续对 D06/第 5 条的“保存到笔记”操作补充确认：**每次点击生成结果的保存入口，
先选择目标笔记，再将该图作为正式附件插入所选笔记**。不沿用上次目标，也不因当前
打开了某篇笔记就自动写入。此决定只授权用户显式选择后的本地笔记写入。

## Consequences

- Product behavior: [Product Spec](../specs/pa-chat-image-generation-product-spec.md)
  定义稳定需求和验收，覆盖桌面与移动端既有受支持使用范围。
- Architecture / data / safety: 聊天存续期间保留有限的图片任务及生成来源记录，
  删除对应聊天内容时清除这些记录并保留图片文件，复用图片资产服务；
  不引入任意文件写权限、公共图床、通用任务平台或跨设备聊天同步。
- Compatibility / migration: 本决定仅解除 DEC-030 中 B-133 的延期边界；B-129 原文件、
  静态媒体、保存和恢复约束以及 B-132/B-134 的延期继续有效。B-135 原有范围不重开。
- Work created: [Feature Home](../../development/active/chat-image-generation/README.md)
  连接技术设计与唯一 Tracker。实现前需独立审阅 SDD 并获得实施授权。

## Delivery Constraints — Owner Amendment 2026-09-18

Owner 在要求完整保留讨论细节后，进一步明确本功能交付约束：**不要过度设计、
不要过度测试；除非存在移动端强相关依赖或具体平台风险，优先使用 Obsidian Desktop
与 CLI mobile simulator 完成验证。** 本节修正此前笼统的移动端真机验证措辞。

- 以满足已确认需求的最小合理改动为目标，复用现有图片、Chat、存储和公开 API。
  新模块/抽象须解释当前必要性；SDD 的 Proposed 名称不要求逐一新建类、服务或数据库。
- 每项测试回答一个尚未覆盖的需求或风险；同一行为的有效证据复用，不穷举
  provider × 模型 × 平台 × 尺寸 × 输入方式的组合，不重复跑已覆盖的 build/full gate。
- 通用行为在 Desktop 验证；移动布局、控件可达性及适用交互优先 CLI mobile
  simulator。仅对实际依赖原生移动能力或已知平台差异的部分补最小真机案例，
  在 Tracker 写明具体依赖/风险、替代证据不足的原因和通过条件。
- 不能把模拟器标成真机证据，也不能借精简测试缩减已确认功能、跳过确实相关的
  平台问题或已有必要的集成/发布门禁。不受本功能影响的其他 track 真机要求不变。
- [讨论细节验收映射](../../development/active/chat-image-generation/sdd.md#13-discussion-detail-traceability)
  将选择及其细节关联至 REQ/AC；实际执行结果只写 Tracker。

## Revisit Trigger

Wan 实际接口无法满足编辑、数量、异步身份或恢复要求；平台无法完成约定的复制/下载；
迁移会改变已有笔记行为；需要新 provider、额外上传服务、自动多次收费、跨设备任务或
更宽媒体支持时，先给 Owner 具体证据与偏差选项，再修订本决定。
