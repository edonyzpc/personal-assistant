# DEC-056 — 显式启用的 PA 标签外观与稳定自动配色

Decision ID: DEC-056
Status: Accepted
Updated: 2026-10-09
Authority: 2026-10-09 本会话中用户对自动配色、默认关闭、首版范围与完整名称独立配色的明确确认。
Work item: B-166

## Context

用户希望将 Obsidian 标签呈现为 Notion 风格：低饱和柔和底色、同色系文字、
微圆角矩形、紧凑间距、无阴影及常驻边框。用户提供了九组浅色配色参考。
该能力跨越 Obsidian 正文、属性与 PA 自有界面，必须明确启用边界、标签身份、
覆盖范围及关闭后的恢复行为，避免安装 PA 就接管宿主外观。

本决定依据本会话的产品确认，不以 Agent 建议或文档状态本身作为批准证据：

| 来源 | 已确认内容 | 授权边界 |
| --- | --- | --- |
| 用户明确改选自动配色方案，2026-10-09 | 按标签名称自动固定分配柔和颜色，同名始终同色 | 不包含 AI 判断语义或逐标签手工配色 |
| 用户明确要求开关默认关闭，2026-10-09 | 未启用时不能替换系统标签样式 | 不包含安装或升级时自动开启 |
| 用户对推荐方案回复“接受推荐”，2026-10-09 | 首版覆盖范围与完整名称独立配色 | 不包含侧栏、搜索补全或其他形似标签的控件 |
| 用户要求文档落地及 SDD 设计、开发和测试计划，2026-10-09 | 固化产品契约并准备后续交付设计 | 尚未授权运行时代码实施、部署或 Git/release 动作 |
| 用户后续要求根据 B-166 完成所有开发测试，并因 GLM 限额直接使用 GPT，2026-10-09 | 授权既定范围的实现、测试、必要隔离本地部署和验收 | 不扩展至 commit/push、closeout 或 release |

## Options Considered

| Option | Benefits | Costs / risks | Why selected or rejected |
| --- | --- | --- | --- |
| 所有标签使用同一种柔和色 | 最少视觉变化，无配色管理 | 缺少多色区分 | 用户已选择自动多色 |
| 手工指定每个标签或分类的颜色 | 可由用户表达明确语义 | 增加配置与维护负担 | 首版不采用，不增加逐标签配置 |
| 按完整标签名称稳定分配九色 | 开箱即用，同名跨界面保持一致 | 不同名称可能同色，改名可能换色 | 用户已确认，采用 |
| 子标签继承顶层或父标签颜色 | 同一层级分支容易识别 | 颜色按分支而非完整名称分配 | 用户接受完整名称独立配色，不采用继承规则 |
| 安装或升级后默认启用 | 用户立即看到新外观 | 未经选择改变主题和 snippets 的现有呈现 | 用户明确要求默认关闭，不采用 |

## Decision

1. 提供默认关闭的标签外观开关。新配置和旧配置中缺失该字段时均为 `false`。
   只在用户开启后接管支持范围内的标签外观；持久化用户选择，启动、升级和
   界面重建不得擅自改变已有选择。
2. 首版覆盖正文阅读、Live Preview 与 Source mode 的正文标签、Properties 的
   `tags` 属性，以及 PA 呈现的真实笔记标签。不改变标签侧栏、搜索/补全列表、
   普通 list 属性，也不处理 PA 状态、来源或数量 chips。
3. 配色使用完整标签名称：去掉语法前导 `#`、统一大小写，保留中文及 `/` 层级。
   父子标签分别计算，不继承父标签颜色；不截取末级名称。
4. 使用固定九色集合与稳定映射，同一规范化名称不随遍历顺序、其他标签增删、
   设备或重启变化。颜色允许重复，改名后可能换色；颜色不自动承载优先级、
   完成状态或其他语义。
5. 采用约 `3px` 圆角、约 `2px 6px` 内边距、柔和底色及同色系文字；协调正文
   行高并继承用户字体缩放。无阴影和常驻装饰边框，保留可辨识的键盘焦点。
   浅色使用用户提供的九组参考；深色采用同色系暗底浅字，并在实现阶段验证。
6. 只改变呈现，不改标签文本、Markdown、属性数据、层级、搜索语义及原生交互。
   不增加 AI、网络调用、逐标签配置或为配色建立持久化标签清单。
7. 关闭或卸载时清理本功能的标记、监听与编辑器扩展，使当前主题和用户启用的
   CSS snippets 重新决定标签外观；恢复目标不是 Obsidian 出厂样式。已打开、
   新打开与重新打开的视图及其他窗口均遵守当前开关状态。

## Consequences

- Product behavior: 这是一项可忽略、可关闭的外观能力；用户无需维护颜色规则。
  同名同色不意味着不同名称必须使用不同颜色。
- Architecture / data / safety: 配色仅依赖标签名称和固定规则。本功能新增持久化
  数据仅为外观开关，沿用 PA 设置存储；不修改笔记，不外发标签，不创建独立标签库。
- Compatibility / migration: 缺失设置安全落为关闭。开启时只作用于明确支持的标签
  节点；关闭后由当前主题和 snippets 接管，保留其他用户设置及宿主交互。
- Work created or removed: 技术契约覆盖阅读渲染、编辑器、Properties、PA 标签及
  多窗口生命周期；不创建配色管理器、AI 分类能力或新的标签数据体系。
- Delivery boundary: 产品决定不自动授权实施或 Git/release。后续开发测试与 closeout
  已按上述用户指令完成，独有历史证据紧凑保留；远程推送与发布仍分别授权。

## Revisit Trigger

- 用户明确提出颜色应表达既有语义，或要求手工指定颜色、父子继承、扩大覆盖范围。
- 真实交互证据表明当前宿主渲染无法在保留编辑、搜索及属性交互的前提下满足范围。
- 兼容性证据表明需要改变数据、存储、主题接管或关闭恢复边界。

上述触发器允许重新评估，不自动授权扩大实现或改变已确认范围。
