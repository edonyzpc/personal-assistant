# DEC-043 — PA Agent 问答范围硬约束与 Runtime 演进

Decision ID: DEC-043
Status: Accepted
Updated: 2026-09-24
Authority: Owner 在当前架构评审讨论中接受五项演进方向，确认三种范围、默认/记忆与图标优先，并接受硬约束、上下文取舍和运行中切换方案；随后明确要求落地产品设计文档。
Work item: B-149

## Context

基于 `master@6fce3824` 的评审，Owner 选择用用户可见的问答范围硬约束，降低模型判断取材权限的负担。原型参考只提供三选一交互思路，不授予外部产品文案或机制在 PA 中的权威。

当前 [DEC-042](./dec-042-agent-task-source-boundary.md) 不提供本轮硬范围控件；普通自由语言来源要求由 Agent 遵循，Host 保留明确设置与执行保护。新的选择需要覆盖历史、摘要和派生材料，否则禁用新读取仍不能兑现用户对范围的预期。

同时，执行事实与领域结果、动作历史、恢复进展、取消、来源版本及资源预算需要分清责任。演进应服务于[“随手记下，需要时自然浮现”](../pa-product-north-star.md)，不把 PA 扩展成让用户管理复杂流程的通用 Agent 平台。

## Options Considered

| Option | Benefits | Costs / risks | Disposition |
| --- | --- | --- | --- |
| 继续完全依靠自由语言或模型声明限制本轮来源 | 无额外入口 | Host 不能独立确定用户选择，模型解释错误会影响权限边界 | 保留自由语言的细化作用，不作为硬范围来源 |
| 三种显式范围，只限制新工具调用 | 实现较窄，追问更连贯 | 历史、个人背景、摘要和提供方状态仍可能带入范围外材料 | 不采用 |
| 三种显式范围，覆盖实际请求与派生上下文 | 用户选择可被确定性执行 | 收紧/跨范围时可能需要重述追问条件 | Owner 接受 |
| 模型重新整理混合历史，再认定为安全上下文 | 表面保持连续 | 无法确定不再包含或依赖范围外资料 | 不作为硬约束的依据 |
| 运行中切换立即取消并重跑 | 当前任务立即使用新范围 | 意外中断、重复成本与恢复复杂度 | 不采用；下一次新请求生效，用户仍可主动取消 |
| 将 Host 保护全部删除，交给模型自治 | 循环代码可缩短 | 授权、执行事实、重复副作用和真实交付失去保证 | 不采用 |

## Decision

### D1 — 范围与体验

采用**我的笔记 / 网络资料 / 综合模式**。新会话默认我的笔记，同会话记住选择；旧会话兼容可证明的原有效权限。输入区以图标简洁显示，菜单、说明和无障碍名称可识别完整含义。“综合模式”取代此前讨论中的“笔记与网络”，不使用暗示模型自动掌握权限的“智能模式”。

### D2 — 硬边界与连续性

用户选择与当前权限共同约束实际取材、模型输入、辅助调用及派生材料。范围不依赖关键词、模型敏感性判断或模型自报。当前用户明确提供的合法材料可用，但不扩大到其他来源，也不绕过 Data Boundary。

范围收紧或跨范围时，只复用来源可靠且相容的上下文；混合或无法证明相容的内容整体不入模，不能以引用列表或模型改写作为清除来源的证明。历史仍可见，必要时从新的模型上下文继续；只在确实缺失必要条件时请用户补充。Owner 接受**硬边界优先于部分跨范围追问的连续性**。

### D3 — 生效与独立权限

发送时固定本次范围，运行中切换只影响下一次新请求，不自动取消、重启或重复调用；用户可以主动取消。真实来源撤销和能力关闭继续及时生效。选择资料范围不授予写入、删除、配置变更、付费操作或隐式 Writing 权限。

### D4 — 五项架构演进

1. Host 守明确权限、执行事实与资源生命周期；主 Agent 理解任务、自主取材及恢复；领域模块解释自己的结果。执行成功、无匹配、作品生成、等待确认和任务完成分别表达。
2. 保留可关联的助手动作、调用参数与结果，按需压缩旧/大上下文；不把平铺观察和更多纠正提示作为丢失动作历史的长期补偿。收益由实际任务对照证明。
3. 分离连续同因无进展与全程资源累计；真实进展可重置恢复片段。取消覆盖准备/等待，不被无响应只读准备阻塞；已读正文绑定实际读取版本，不冒充后续新版本。
4. 上下文预算考虑模型窗口、输出预留与实际使用，辅助摘要有可观察成本收益。保留 DEC-040 的 30 分钟尝试、完成导向、前后台机会、等待释放无用名额及重载后用户继续；不批准新的任意总费用或更小后台预算。
5. 清理无生产消费者的策略分支，领域特判回归领域；保留有效保护，以小型真实 runtime 任务基线验证产品质量，而不只检查静态 fixture 或 bundle 变化。

### D5 — 2026-09-24 Owner 接受的后续细化

- **过程与兼容**：压缩保留任务目标、限制、关键证据、已尝试查询、调用对应关系及未完成操作状态；保留现有模型兼容范围，原生与兼容投影均须保全必要语义。容量不足不能静默丢掉关键条件。
- **结果所有权**：领域模块提供执行/产物事实，主 Agent 判断任务覆盖程度，Host 拦住可确定的授权、回执与必要产物不一致。清理退役策略不减少有效能力与旧记录读取/恢复保护。
- **缺少依据的默认答法**：区分正常无匹配、缺少任务必需材料及检索不可用；笔记任务缺少依据时默认不自动附送通用答案，用户明确要求通用解释时再回答并区分来源。不因零命中固定加查或扩大范围。
- **投入与降级**：采用围绕任务目标和进展的一套策略，不新增快答/深度模式或按意图分类强制额度。可选摘要按需执行、同材料不反复生成、独立计账；辅助预算耗尽只停止可选优化。具体参数由基线确定，既有长操作与主任务恢复合同不变。
- **评测与取舍**：固定样例预先标注必要证据、任务目标和允许差异；完整统计摘要/重试成本及有用结果/最终交付时间。确定性底线必须通过；同等质量优先更快更省，明确提升任务正确性时允许有证据支持的增加，明显增加时再提交具体取舍。模型评分不能独自替代验收。

Owner 随后要求复核是否仍有待决点；上述细化已确认，不重复请求批准。消息格式、模块接口、参数及样例属于技术设计与测量工作，实质改变产品/权限/兼容/成本承诺时才重新决策。

### 生效与替代边界

这是**已批准的目标产品设计**，并非已实现或发布；具体行为与验收由 [B-149 Product Spec](../specs/pa-agent-runtime-evolution-product-spec.md)承接。

- 局部替代 DEC-042 中“不增加本轮结构化取材控件”的未来边界：新增用户显式选择的 Host 硬约束；不恢复模型自报授权或 Host 对任意自由文本的权限解释。
- 在问答范围限制内继续适用“Chat 可读资料可用于已启用模型与搜索”的规则。我的笔记禁止网络取材，网络资料禁止自动笔记背景；综合模式不另设内容敏感性外发层或逐次搜索确认。
- 为执行显式范围而保留必要来源/派生关系，不代表重启 DEC-042 已否决的敏感内容分类、受保护标记和目的地确认体系。
- DEC-042 的显式 Writing、独立动作保护、Data Boundary 完整排除与结构化未完成报告，以及 DEC-040 的既有预算/恢复合同继续有效；B-146 已交付事实不被改写。
- Chat 控件不改变独立 Pagelet/Memory 的触发、权限与成本边界。B-147 排除例外、B-148 更宽事实核实不由本决定自动启动。

## Consequences

- Product behavior: 默认回到笔记，范围可预期；少一次隐式判断，但收紧或跨范围追问可能需要用户重述条件。
- Architecture / data / safety: 工具、上下文、摘要/恢复与物理请求共用可确定的边界；动作结果由对应 owner 提供，动态撤销与材料版本分别处理。
- Compatibility / migration: 同会话选择可恢复；旧会话保守映射有效权限；旧历史和作品继续可查看，不伪造缺失来源，不为迁移自动调用模型。
- Work created or removed: B-149 承接产品设计与待实施工作；后续清理退役策略并补足真实任务评测，不新建泛化编排平台。本次文档不改变 runtime。

## Revisit Trigger

- 实际跨范围追问中，混合来源整体排除持续阻断核心笔记复用任务；若要换取更高连续性，必须明确重新决定可接受边界。
- 现有存储或 provider 会话机制无法证明过滤后的真实请求，需改变兼容、存储或产品承诺。
- 可重复的任务成本、时延或无进展证据表明需修改预算政策；不得只凭后台身份或代码复杂度收紧。
- 用户明确要求新的来源类型、Data Boundary 例外、跨重载自动执行或更广动作权限。
