# DEC-028: 多模态 Chat + 基于图片的社交媒体文案辅助

| Field | Value |
|-------|-------|
| Status | Approved |
| Date | 2026-08-11 |
| Decision | Build（分层实施） |
| Sizing | L（分层拆解为 M + S-M + M-L） |
| Stakeholders | 产品（edony）、天使用户反馈 |
| Related | North Star, AI Chat, Memory/Relational Context |

## 需求原文

用户希望根据提供的图片（旅行照片、日常记录照片等），PA 帮生成一段文案，
方便在小红书、微信朋友圈、X、微博等社交媒体发布。

## 决策结论

多模态是 AI Chat 的基础设施级能力缺失，文案辅助是 relational context
价值的自然展示场景，图片生成可作为付费增值。三层叠加 ROI 合理。

### 实施优先级

1. **基础层**：AI Chat 多模态输入支持（Size M）
2. **应用层**：文案场景 prompt + vault context 风格注入 + capture 回流（Size S-M）
3. **增值层**：图片生成能力，可考虑付费功能（Size M-L）

### 关键事实

- PA 当前 AI Chat 不支持图片输入，这是基础能力缺口
- 用户期待基于 vault 积累的个性化风格适配，PA 有独特数据优势
- D 策略（生成即 capture）让功能使用自然反哺 vault 数据飞轮
- 冷启动通过 C（高质量默认）+ D（使用即积累）解决，不依赖预先投入

### 如果未来需要重新评估

- 当多模态 Chat 上线后用户实际使用率低于预期时
- 当风格学习的精准度不足以让用户感知到差异时
- 当主流竞品（Obsidian 官方/其他笔记工具）集成同等能力时

## Phase 1: 还原用户与场景

### 用户画像

| 维度 | 判断 |
|------|------|
| 身份 | 天使用户，刚接触 Obsidian 和 PA，非重度内容创作者 |
| 频率 | ~3次/周发社交媒体，中等频率 |
| 技术能力 | 不知道 ChatGPT 能做这个，用过豆包但不满意 |
| 为什么找 PA | 核心期待是**个性化风格**——"PA 了解我，能写得像我" |
| 代表性 | 单一天使用户，但"带娃分享"是大众场景 |

### 场景还原

| # | 触发 | 意图 | 当前行为 | 摩擦 |
|---|------|------|----------|------|
| A | 带孩子旅行，拍到可爱瞬间 | 想快速分享 | 只有照片没文字，卡在写配文 | 不想花时间写/改 |
| B | 刷社交媒体看到共鸣图片 | 想转发+表达自己的感触 | 有初步想法但觉得表达不够好 | 写出来觉得"不够有逼格" |

### 阶段判断

用户的核心痛点不是"没有工具生成文案"（豆包能做），而是**生成的风格不像
自己/不够好**。他对 PA 的期待建立在"PA 了解我"这个假设上。

注意：用户是刚接触 PA 的天使用户，vault 几乎为空——期待与 PA 当前能力之间
存在冷启动 gap。

## Phase 2: 拆解真实需求

### 需求分层

```
表层：我要一个"图片 → 社交媒体文案"的功能
     ↓ 为什么？
中层：我想轻松地把生活瞬间分享出去，配文要有质感
     ↓ 为什么这个重要？
深层：我想表达自己、记录生活，但创作能力/时间是瓶颈
```

### JTBD

> **When** 我有一个想分享的瞬间或感触，
> **I want to** 获得文字优美、有洞察感的表达，且越来越贴合我的审美，
> **So that** 分享出去的内容代表我的品味，而不只是"AI 味"的填充文字。

### Kano 分层

| 层次 | 内容 | 分析 |
|------|------|------|
| 基本型 | 给图生成一段通用文案 | 豆包已能做，用户试过且不满意 |
| 期望型 | 文案风格贴合特定平台（小红书 vs 朋友圈） | 专用工具部分解决 |
| 兴奋型 | 文案"像我写的"——符合我的表达习惯和审美 | **用户真正期待的差异化** |

### 风格需求细化

用户对"风格"的具体要求：
- 文字调性：优美，对文字质量有要求（用户喜欢阅读）
- 内容深度：有洞察、有让人心里一惊的思考
- 不是简单的"帮我凑一段话"

### 关键洞察

用户的真实需求不是"生成文案"，而是"AI 写作助手 + 风格学习"。需要的是
一个理解他审美偏好、能写出高质量文字的表达伙伴。场景 A（自拍照分享）和
场景 B（共鸣图表达）本质一致：都是"有素材/感触，需要高质量文字表达"。

## Phase 3: 市场与替代方案

### 现有替代方案地图

| 替代方案 | 用户满意度 | 摩擦点 | 切换到 PA 的动力 |
|----------|-----------|--------|-----------------|
| 自己写 | 低——费时间，觉得写不好 | 能力/时间瓶颈 | 高 |
| 不发/只发图 | 中——凑合但不甘心 | 放弃了表达欲 | 中 |
| 豆包 | 低——试过，风格不满意 | "AI 味"重，不像自己 | 高 |
| ChatGPT/Claude 直接对话 | 未尝试（用户不知道） | 认知门槛 | — |
| 小红书内置 AI | 待确认 | 平台锁定，仅限小红书 | — |

### 竞争空间判断

```
已被充分解决（Red Ocean）：
  → 图片 → 通用文案（任何多模态 LLM）

部分解决（有缝隙）：
  → 平台风格适配（专用工具做得到，但千人一面）
  → 即时高质量文字（好的 prompt + Claude/GPT 能做到，但用户不会用）

未被解决（Blue Ocean）：
  → 持续学习用户审美偏好的个性化写作风格
  → "越用越懂我"的表达助手
```

### 关键问题深入讨论

#### 问题 1：壁垒持久性

"用户不知道 ChatGPT 能做"是一个 6 个月内必然消失的壁垒，不能作为产品
决策的依据。信息差型需求不是产品机会，是时间窗口。

真实的对比不是"PA vs ChatGPT 的能力"，而是"用户知道了 ChatGPT 后还选
PA 的理由是什么"。

可能的持久优势：
- 零配置的风格持续性（不用每次描述偏好）
- **生活上下文加持**——PA 知道你的经历，文案不只是看图说话，而是带有用户
  真实记忆和感受。这是通用 LLM 做不到的。

**结论**：PA 做这个功能的定位不是"打败 ChatGPT"，而是 relational context
的衍生能力。不构成对竞品的壁垒，但确实是 PA 的自然延伸——更适配使用者、
更深入的洞察形成更符合使用者调性的输出。

#### 问题 2：风格学习是真壁垒还是好 prompt 就够？

风格可拆为五层：调性、词汇偏好、句式结构、思维模式、情感表达。

- 好 prompt 能覆盖：调性（7/10）、词汇偏好（5/10）
- 好 prompt 难覆盖：句式结构（3/10）、思维模式（2/10）

用户能描述的是"显性偏好"，写作风格的精髓在"隐性特征"（句式节奏、思维
路径、意象选择）——用户自己都不知道自己有，更写不进 prompt。

但关键现实是：**这个用户不会写 prompt 也不会优化 prompt**，使用方式就是
复制粘贴+输入简单要求。所以真实对比是：

| | 用户对通用 LLM 的实际用法 | PA 的做法 |
|--|--------------------------|----------|
| 输入 | "帮我写个朋友圈文案" | 同样的输入 |
| 上下文 | 只有当前图片 | 图 + vault 中的记录 |
| 风格适配 | 模型默认风格（AI味） | 从历史记录中提取的偏好 |

PA 的优势不在于"壁垒"，在于**默认体验更好**——用户不需要额外做任何事，
PA 自动比"裸用 LLM"好一点。这个"好一点"不是颠覆性的，但对已经在用 PA
的用户来说是免费获得的附加价值。

风格学习的前提条件：vault 里有足够的**用户自己写的、有情感和表达的文字**。
如果 vault 全是结构化笔记和待办，PA 对风格的理解不会比通用 LLM 好。
这个天使用户 vault 内容为日常混合记录，风格样本有限。

**结论**：风格学习不是"真壁垒"也不是"伪需求"，是有条件成立的优势。

#### 问题 3：冷启动困境

冷启动策略确定为 **C + D 为主，B 为辅**：

```
第一次使用（vault 空）
  → C：高质量默认体验兜底，确保首次不比豆包差
  → D：生成结果自然存入 vault，每次使用都在积累风格数据
       ↓
使用 3-5 次后
  → PA 已有用户满意的文案作为风格参照
  → 开始体现个性化差异
       ↓
可选触发 B
  → 用户主动需要时引导：提供过去满意的文案样本加速学习
```

| 策略 | 角色 | PA 调性匹配度 |
|------|------|-------------|
| C（高质量默认） | 兜底，确保首次体验 | 中——不是 PA 独特能力，但必要 |
| D（文案即 capture） | 飞轮启动，生成变积累 | 高——完全契合"随手记下" |
| B（主动获取样本） | 加速器，用户需要时触发 | 中高——不强制，提供选项 |

D 策略的特殊价值：把一个本来偏离定位的"生成"动作，转化为符合定位的
"capture"动作——**生成和积累合一**。

### Phase 3 总结

这个需求的市场空间不在"打败 ChatGPT"，而在"让 PA 用户觉得留在 PA 里
做这件事是自然的、顺手的、而且越用越好"。竞争对手不是 ChatGPT 的能力，
而是用户"切出去用别的工具"的意愿——只要 PA 里做这件事的体验 ≥ 切出去的
体验，用户就不会走。

## Phase 4: 产品匹配度评估

### 战略对齐检查

| 维度 | 问题 | Yes/No | 理由 |
|------|------|--------|------|
| 定位 | PA 核心要解决的问题吗？ | No（单独看）/ Yes（作为衍生） | PA 核心是 capture + recall，文案是输出端的应用 |
| 差异化 | 有明确差异化优势吗？ | 有条件的 Yes | vault 积累后优于裸用 LLM |
| 用户群 | 目标用户吗？ | Yes | 天使用户，已在用 PA |
| 资源 | 投入产出比合理吗？ | Yes | 多模态是基础设施，文案只是场景之一 |
| 协同 | 能强化现有能力吗？ | Yes | D 策略反哺 vault 数据和风格学习 |
| 风险 | 会模糊定位吗？ | No | 作为 AI Chat 的自然能力，不独立宣传为"文案工具" |

### 能力-意愿矩阵

|  | **该做** | **不该做** |
|--|---------|-----------|
| **能做** | AI Chat 多模态 + vault context 风格辅助 | 独立的"社交文案生成器"模块 |
| **不能做** | — | — |

### 北极星校验

PA 的价值链：**Capture → 积累 relational context → 在输出端帮到用户**。

North Star 的"Less generation, more return"约束的是生成的来源（不要凭空
编造），不是禁止生成本身。基于用户记忆和风格的生成，本质是 return 的一种
输出形态。

PA 最终还是要在输出上帮到使用者——基于 relational context（memory）衍生
AI Chat 的能力，与 North Star 完全不冲突。

| 层 | 内容 | Size |
|----|------|------|
| 基础层 | AI Chat 多模态输入支持（图片理解） | M |

| 增值层 | 图片生成能力（通知/分享卡片，可付费） | M-L |
| **总计** | | **L** |
